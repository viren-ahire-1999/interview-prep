AI Engineer

This course is a single path from “what is a model?” to shipping retrieval, agents, evaluation, and production systems. It is written to be easy to read and still specific enough to use at work. You will not train a frontier model here. You will learn the judgment an AI engineer is hired for: pick the cheapest honest system, measure it, and keep it safe.

What “complete” means here

Foundations Classical ML Deep learning LLMs / RAG / agents Eval + safety MLOps

An AI engineer sits between research and product. You use Python, data, APIs or open models, and software engineering. You do not need a PhD. You do need to explain trade-offs without hiding behind a library name. Practice items are labeled practice — not claimed official company questions.

You will be able to

  • Explain ML vs DL vs LLMs in plain language
  • Split data without leaking the future into the past
  • Choose a metric that matches the product cost of errors
  • Sketch a transformer and why attention replaced recurrence
  • Design RAG with chunking, citations, and a fail path
  • Decide prompt vs RAG vs fine-tune vs agent
  • Evaluate quality without trusting a single “LLM judge”
  • Talk cost, latency, observability, and safety in a design

Artificial intelligence is the umbrella: machines doing tasks that look like judgment. Under it you almost always mean one of these:

LayerIdeaUse when

Shape errors are the tax. Say shapes out loud: (batch, features) for tabular, (batch, time, dim) for sequences. If two arrays will not broadcast, you are not ready to debug a transformer.

Tensors are just arrays with a story

A tensor is a multi-dimensional array. The story is the axis names:

  • B — batch (how many examples at once)
  • T — time / tokens (how long the sequence is)
  • D — width of a vector (embedding size)
  • C — classes or channels
logits[B, T, V] → for each item, each token, a score per vocab word labels[B, T] → the correct next token Never add B and T by accident. That is a silent bug.

In Python you check array.shape after every non-trivial line until it is muscle memory.

Vectors and ‘close’

A vector is a list of numbers. In AI it often means “this item’s coordinates in meaning-space.”

The dot product a·b = a0*b0 + a1*b1 + … is large when they point the same way. Cosine similarity is the dot product after both vectors are stretched to length 1 — so “long” vectors do not automatically win.

Python
import numpy as np

def cosine(a, b):
    a = np.asarray(a, dtype=float)
    b = np.asarray(b, dtype=float)
    return float(a @ b / (np.linalg.norm(a) * np.linalg.norm(b) + 1e-12))

print(cosine([1, 0], [0.9, 0.1]))  # close to 1
print(cosine([1, 0], [0, 1]))      # 0 — orthogonal

A loss is a number that is worse when the model is more wrong. Training is “nudge parameters so loss goes down.” The gradient is the direction of steepest increase; we step the opposite way. You do not need to derive backprop on a whiteboard on day one — you do need this picture.

loss | * (start) | / | * | * |_*________ parameters step opposite the slope

Probability: a model often outputs a number in [0, 1]. That is not a promise. Calibration asks whether “0.8” is right about 80% of the time. Likelihood is “how unsurprising was the data under this model.”

Linear algebra you will actually use: multiply a matrix by a vector (a layer), transpose, norms. Calculus: derivative of a sum is the sum of derivatives. That is enough to start.

Data and leakage

Jump to practice (6) →

Splits are a contract with the future

You fit on train. You make modeling choices on validation (also called dev). You touch test once at the end — or you have used it as a second validation set and you are lying to yourself.

[ train | val | test ] choices report Time data: split by DATE, not by shuffle. User data: put a user entirely on one side.

Leakage is when information that would not exist at prediction time sneaks into training. Examples:

  • Using “updated_at” after the label was set.
  • Normalizing with the test-set mean.
  • A feature that is the label in disguise (“refunded_amount” to predict “will_refund”).
  • Random split on a time series so tomorrow’s pattern is in today’s train.
Python
# Time split — honest
df = df.sort_values("ts")
cut = int(0.8 * len(df))
train, rest = df.iloc[:cut], df.iloc[cut:]
# Then split rest into val/test the same way.

# Leak — do not
# scaler.fit(all_data); scaler.transform(train)
Labels are data. If humans labeled in a rush, the model will learn the rush. Sample the errors; do not only stare at a leaderboard.

Garbage in is not a slogan — it is the bug

Class imbalance: 99% “not fraud.” Accuracy of 99% is a model that never flags. You will fix this with the right metric, not with a fancier net first.

Missing values: “unknown” is information. Blindly filling with the mean can hide a sensor that is broken.

Duplicates: the same row in train and test is a free point and a production miss.

Supervised learning

Jump to practice (6) →

Learn a function from examples

Supervised learning: you have inputs X and a target y. The model learns a function f(X) ≈ y. Classification: y is a category. Regression: y is a number.

for many steps: predict ŷ = f(x) loss = how wrong(ŷ, y) nudge f so loss drops stop when val loss stops improving

Underfit: too simple — train and val both bad. Overfit: memorizes train — train great, val poor. The validation curve is how you see it.

Python
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report

Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.2, stratify=y, random_state=0)
clf = LogisticRegression(max_iter=1000)
clf.fit(Xtr, ytr)
print(classification_report(yte, clf.predict(Xte)))

Unsupervised: no y (cluster customers). Self-supervised: invent y from the input (mask a word, predict it) — that is how LLMs pretrain.

A metric is a product decision

Accuracy is “how often was the label right.” It is a lie when classes are rare or when errors have different costs.

  • Precision — of the items you flagged, how many deserved it. Low precision = false alarms (user fatigue, wasted reviews).
  • Recall (sensitivity) — of the items that deserved a flag, how many you caught. Low recall = missed fraud / missed cancer.
  • F1 — harmonic mean of the two when you need a single number.
  • ROC-AUC — ranking quality across thresholds. Useful, not a substitute for a chosen threshold.
  • PR-AUC — better story under imbalance than ROC-AUC.
  • Calibration — do predicted probabilities match frequencies?
  • Regression: MAE (typical error), RMSE (punishes big misses).
Actual yes Actual no Pred yes TP FP ← precision = TP/(TP+FP) Pred no FN TN ← recall = TP/(TP+FN)

Deep learning starts here

Neural nets

Jump to practice (6) →

A neuron is a weighted sum plus a bend

One neuron: multiply inputs by weights, add a bias, then apply a non-linearity (ReLU = max(0, x), sigmoid, tanh). Without the bend, a stack of layers is still one linear model — uselessly shallow.

x1 ─w1─┐ x2 ─w2─┼─► sum + bias ─► ReLU ─► hidden x3 ─w3─┘ Many neurons in parallel = a layer. Many layers = a multi-layer perceptron (MLP).
Python
import numpy as np

def relu(x):
    return np.maximum(0, x)

def forward(x, W1, b1, W2, b2):
    h = relu(x @ W1 + b1)     # x: (B, in)
    logits = h @ W2 + b2      # (B, classes)
    return logits

Softmax turns logits into a probability distribution (they sum to 1). Training uses cross-entropy with the true class: “how surprised were we.”

Backprop is the chain rule run in reverse: each weight gets a share of the blame for the loss. Optimizers (SGD, Adam) decide the step size. You will use Adam and a learning-rate schedule long before you write your own CUDA kernel.

Vanishing gradients: stacked sigmoids squash signals. ReLU and residuals (skip connections) were engineering answers. Transformers use both residual and layer-norm.

Structure in space and time

CNNs and sequences

Jump to practice (5) →

Images share patterns; text used to walk left to right

A convolution slides a small filter (e.g. 3×3) across an image. The same weights detect an edge everywhere — parameter sharing. Stack filters and you get textures, then object parts. CNNs made vision practical before transformers ate that too.

Image 5×5, filter 3×3 → response 3×3 (valid) Each output cell = dot product of the window with the filter + ReLU + optional pooling (downsample)

Sequences (text, audio): older models were RNNs / LSTMs — they read one token at a time and kept a hidden state. They struggle with long-range links and do not train as easily in parallel. That is why attention won for language.

You still meet CNNs in vision APIs, medical imaging, and as a cheap tower next to a text model. You still meet recurrence in some speech and time-series stacks. Know why they exist; do not start a new NLP system on a vanilla LSTM in 2026 without a reason.

The modern core

Attention and transformers

Jump to practice (6) →

Attention: every token looks at every token

Self-attention lets each position build a weighted average of the others. Weights come from similarity of a query (what I am looking for) and keys (what each position offers). Values are the content that gets mixed.

Python
import numpy as np

def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)

def attention(Q, K, V):
    # Q,K,V: (T, D)
    scale = Q.shape[-1] ** 0.5
    weights = softmax(Q @ K.T / scale)   # (T, T)
    return weights @ V                   # (T, D)
tokens: the cat sat Each row of weights: how much this token mixes the others ‘sat’ may put mass on ‘cat’ — a subject for the verb + residual + MLP after attention = one transformer block

Multi-head: run attention several times with different projections so one head can do syntax and another a different pattern. Positional information is added because raw attention does not know order. Encoder sees the whole sequence; a decoder for generation attends only leftward (causal mask) so it cannot peek at the future token.

An LLM is (mostly) a stack of decoder blocks trained to predict the next token on a huge text mix, then later aligned with instructions and preferences. That is the whole magic trick — scale plus this architecture.

Context window is how many tokens fit in that attention matrix. Cost grows steeply with length (classically T²). Long-context models change the engineering, not the product duty to retrieve the right facts.

RAG

Jump to practice (8) →

Retrieval-augmented generation

RAG means: find relevant company text (or tickets, or code), put it in the prompt, ask the model to answer from that. It does not make the model truthful. It makes the model groundable.

ingest → chunk → embed → index query → embed → retrieve top-k (+ rerank) → prompt(system + excerpts + question) → answer + citations → if weak hits: refuse / ask clarify / ticket

Chunking: too small → no context. too large → diluted similarity and fat prompts. Start ~400–800 tokens with 10–20% overlap, then measure. Split on headings for policies; on functions for code.

Metadata filters (space, time, ACL) happen before or with the vector search. A user must not retrieve another tenant’s chunk.

Python
def answer(question, index, acl):
    hits = index.search(question, k=8, filter=acl)
    hits = [h for h in hits if h.score >= MIN]
    if len(hits) < 2:
        return {{"refuse": True, "answer": "I do not have enough policy text."}}
    prompt = build_prompt(question, hits)
    out = llm.generate(prompt)
    return validate_cites(out, allowed={{h.id for h in hits}})
What RAG does not fix. Wrong corpus, stale index, ambiguous question, model ignoring excerpts, or a task that needs multi-step tools (then you need an agent or a workflow).

RAG breaks in boring, testable ways

  • Chunk cut a table in half → retrieval of nonsense. Test with table-heavy pages.
  • Index rebuilt weekly, policy changed today → confident old answer. Version documents; show “as of”.
  • Citations invented. Only allow IDs you injected; strip the rest.
  • Top-k is 20 and the answer is in #19 — the model never reads that far. Rerank; or pack fewer, better chunks.
  • Query is slang, chunk is legal English — hybrid search (keyword + vector) often wins.

Eval RAG in two layers: retrieval (was the needed chunk in top-k?) and generation (was the answer supported?). Do not average them into one vanity score on day one.

Weights

Fine-tuning

Jump to practice (6) →

Change weights only when the contract is style or a narrow skill

Fine-tuning continues training so the model’s weights shift toward your examples. LoRA (and friends) train small adapter matrices instead of the full net — cheaper, easier to swap.

Fine-tune when:

  • You need a stable format or tone that prompting still misses after good examples.
  • A narrow specialist skill (classify tickets into your 40 codes) and you have hundreds of clean labels.
  • You must run a smaller model on-prem and recover quality.

Do not fine-tune to “add facts.” Facts go stale; use RAG. Do not fine-tune on 30 rows. Do not fine-tune to fix a broken eval — you will overfit the eval.

Need new facts? RAG / tools Need tools / workflow? Agent or graph Need style / schema? Prompt + schema first Still failing + data? Then LoRA / SFT
Data quality dominates. A dirty SFT set teaches your mess at higher confidence. Dedup, have a held-out eval that is not in train, and keep a prompt-only baseline so you know you bought something.

Loops

Agents

Jump to practice (6) →

An agent is a loop with tools and a stop

A chain is a fixed pipeline (retrieve → answer). An agent may choose tools, see results, and repeat. That power is also how it loops, spends money, or calls delete.

while steps < N and not done: model → (final answer) OR (tool name + args) if tool: run tool in YOUR sandbox → append result halt: N steps, $ cap, timeout, user cancel, policy deny

Tools should be narrow, typed, and permissioned. “Run any SQL” is not a tool; “fetch_order(id)” is. Idempotent tools are easier. Confirm destructive actions with a human.

Memory: the conversation is enough for v1. Long-term memory is another index (RAG over past tickets) — not an unbounded scratchpad that never expires.

Default to a workflow. If you can draw the steps (classify → retrieve policy → draft → human), a graph beats a free-roam agent. Use an agent when the next step is truly unknown.

Evaluation

Jump to practice (6) →

If you cannot score it, you cannot ship it

A golden set is a versioned list of inputs plus an expected property: exact answer, must-cite doc, must-refuse, or a rubric. Start with 30–50 hard cases from real users, not 3 complimentary demos.

  • Automatic: exact match, regex, JSON schema valid, retrieval hit-rate, citation validity.
  • Human: spot-check on a rubric (correct / unsupported / harmful / useless).
  • LLM-as-judge: useful for scale, biased toward long and fluent, must be calibrated against humans, and must not grade its own homework only.
  • Online: thumbs, retry rate, escalation to human, latency, cost, deflection.
Python
def score_item(item, out):
    checks = {{
        "schema": valid_json(out),
        "cites_allowed": set(out["cite_ids"]) <= item["allowed_ids"],
        "refuse_ok": out["refuse"] == item["should_refuse"],
    }}
    return checks

Split eval so prompt tweaks cannot silently overfit. Re-run the suite on every prompt, index, and model bump — that is your unit test.

A/B tests need a primary metric chosen in advance. ‘We liked the vibe’ is not a launch criterion.

Do no fluent harm

Safety

Jump to practice (6) →

Safety is product, not a sticker

You will not “solve alignment” in this course. You will ship fewer disasters.

  • PII and secrets — do not log raw prompts that contain tokens, health data, or customer dumps. Redact. Encrypt. Retention limits.
  • Access control — retrieval uses the caller’s ACL. The model is not your authorization layer.
  • Untrusted text — tickets and PDFs can say “ignore the system prompt.” Delimit them; never concatenate blindly into system.
  • Copyright and training data — do not paste licensed code into a public model if policy forbids it. Cite internal docs; do not claim the model “wrote original law.”
  • Over-refusal vs under-refusal — measure both. A bot that never answers is safe and useless.
  • Human escalation — medical, legal, credit, self-harm adjacent: route to a human and a policy. Do not invent treatments.
This course does not teach attacks. If you test robustness, do it on systems you own, with a written scope, and record the fix — not a public recipe.

Serving and cost

Jump to practice (6) →

Tokens, time, and the monthly bill

You pay for input tokens + output tokens (and sometimes cached input at a discount). A token is a chunk of text — rough English rule: 1 token ≈ 4 characters, but measure.

User types → maybe cache prefix (system + tools) → prefill (read the prompt) — compute heavy → decode (one token at a time) — latency of first token + stream Batching: many decodes share a GPU. Good for throughput, can hurt p99.
  • Stream tokens to the UI so TTFT (time to first token) feels fast.
  • Cache embeddings, retrieval results, and unchanged system prefixes.
  • Cap max output tokens. Runaways are a cost bug.
  • Reserve vs on-demand capacity if you self-host.
Python
# Envelope — replace with your prices
def monthly_usd(chats, in_tok, out_tok, price_in, price_out):
    return chats * (in_tok * price_in + out_tok * price_out) / 1000

# 1e6 chats, 800 in, 200 out, $0.50 / $1.50 per 1M tokens
print(monthly_usd(1_000_000, 800, 200, 0.0005, 0.0015))

Self-hosting: you care about batch size, quantization (smaller weights, some quality loss), and a queue. “We will use vLLM” is not a design unless you say the SLA and the GPU SKU.

MLOps

Jump to practice (6) →

Version everything that changes the answer

A model file is one artifact. An AI feature also has: prompt text, tool schemas, chunker, embedding model id, index build id, ACL rules, and decoding params. If you cannot say which bundle served a request, you cannot debug it.

request_id model_id + prompt_id + index_id + embed_id retrieved_ids[] tokens_in / tokens_out / $ user_feedback Store this. Redact PII. Keep enough to replay.

Drift: input drift (users change), data drift (corpus changes), concept drift (the meaning of “urgent” changes). Monitor retrieval scores, refuse rate, and human escalate rate — not only GPU temperature.

Rollback: prompts and indexes must be one-click reversible. Canary a new prompt on 5% traffic with a kill switch. Training jobs get a model registry and a promotion rule (eval suite must pass).

Notebook-to-prod is a smell. The training or ingest job is a pipeline with a SHA. The service reads artifacts, not the data scientist’s laptop.

Deep explanation. Spaces are incompatible. The query encoder must match the document encoder generation.

Common misconception. Just re-embed the query with the new model against old docs.

Follow-up. How do you migrate without downtime?

prodserveQ39

39. What do you cache in RAG?

Short answer. Doc embeddings, public retrieval, stable prefixes. Personalized answers only with ACL in the key and a TTL.

Deep explanation. Wrong keys leak tenants or stale policy. Measure hit rate.

Common misconception. Cache the final answer globally for the same question string.

Follow-up. Write a safe cache key.

genaisafetyQ40

40. Over-refusal vs under-refusal?

Short answer. Over: refuses password reset. Under: invents a drug dose. Measure both.

Deep explanation. Golden slices for must-answer and must-refuse. Kind tone can still refuse.

Common misconception. Safer always means more refuses.

Follow-up. Give one must-answer and one must-refuse for HR.

proddesignQ41

41. What numbers do you guess out loud?

Short answer. QPS, corpus/chunks, latency budget, $ / 1k queries, golden set size. Label them guesses.

Deep explanation. Silence is worse. Ask the interviewer to correct. Those numbers fork RAG vs stuff-context vs self-host.

Common misconception. Only QPS matters, like a backend design.

Follow-up. Guess them for a 2,000-person company wiki.

fundamentalsdataQ42

42. What is label noise doing to your ceiling?

Short answer. If raters disagree 20%, 99% accuracy is a fantasy.

Deep explanation. Measure agreement, build a gold subset, drop sloppy items. A bigger model will fit the noise.

Common misconception. More layers average out label errors.

Follow-up. What statistic would you quote for rater agreement?

mlmetricsQ43

43. ROC-AUC 0.93 and the business is unhappy. Why?

Short answer. AUC ignores the operating point and the review budget.

Deep explanation. You may flag 30% of users. Report precision at the real threshold and the cost.

Common misconception. AUC is the only adult metric.

Follow-up. When is PR-AUC more honest than ROC-AUC?

genairagQ44

44. What is lost-in-the-middle?

Short answer. Models use the start and end of a long prompt more than the middle.

Deep explanation. So dumping 20 chunks can hide the one that matters. Rerank into a short pack; put the best evidence where the model actually looks — and measure.

Common misconception. Longer prompts always help.

Follow-up. How would you test for it?

genaiagentsQ45

45. Why is run_sql a bad tool?

Short answer. Injection, exfiltration, accidental DELETE, no ACL.

Deep explanation. Ship get_order(id) with parameterized SQL inside your code. The model never sees a query string.

Common misconception. The model is good at SQL so it is fine.

Follow-up. How do you make a charge tool idempotent?

prodmlopsQ46

46. Notebook-to-prod — why a smell?

Short answer. No SHA, no replay, no owner, no rollback.

Deep explanation. Jobs produce versioned artifacts. The service reads the registry. Colab is an experiment, not a release.

Common misconception. If it ran once it can run forever.

Follow-up. What belongs in a model registry record?

judgmentevalQ47

47. Demo looked great. Why is that not a launch?

Short answer. Demos are cherry-picked. You need a pre-registered metric and a suite that includes ugly cases.

Deep explanation. Add abandons to the golden set. Watch online task success. Canary.

Common misconception. If leadership clapped, ship.

Follow-up. What ugly cases were missing from the last demo you saw?

fundamentalsroleQ48

48. Do you need a PhD to be an AI engineer?

Short answer. No. You need software engineering, data hygiene, eval, and honesty about limits.

Deep explanation. A PhD helps for novel modeling. Most product AI is RAG, tools, and classical ML with discipline.

Common misconception. Without a PhD you can only write prompts.

Follow-up. What skill gap would actually block you next quarter?

genaillmQ49

49. What does temperature do?

Short answer. Higher → more random next-token samples. Lower → greedy/peaky.

Deep explanation. Use low for extract/classify. Do not raise temperature to ‘fix facts’ — retrieve facts.

Common misconception. Temperature is how smart the model is.

Follow-up. What decoding would you use for JSON?

dlnnQ50

50. Train vs eval mode — why?

Short answer. Dropout and batch-norm behave differently. Inference uses eval().

Deep explanation. Leaving dropout on at serve time injects noise. A common silent bug.

Common misconception. They are the same if you do not use dropout.

Follow-up. What is MC-dropout and why is it not the default?

prodserveQ51

51. Why cap max output tokens?

Short answer. A bug or a loop can write a novel and empty the budget.

Deep explanation. Also timeout, $ breaker, stop sequences. Retries multiply spend.

Common misconception. The model will stop when it is done.

Follow-up. What else multiplies cost besides output length?

genairagQ52

52. Why store as-of on an answer?

Short answer. Policies change. Users (and auditors) need to know which version was retrieved.

Deep explanation. Index build id + document updated_at in the footer. Critical docs get a faster ingest than nightly.

Common misconception. The model knows what is current.

Follow-up. How fast must a legal page go live in your company?

judgmentdesignQ53

53. Name two designs you reject for ‘AI search.’

Short answer. Chat over every SKU; fine-tune on the catalog instead of indexing it.

Deep explanation. v1 is search quality (keywords, filters, rank). LLM rewrite is a later experiment with an IR metric.

Common misconception. Search is solved so we only need GPT.

Follow-up. What IR metric would you put on the poster?

mlfeaturesQ54

54. Why is raw user_id a bad numeric feature?

Short answer. Trees memorize identities. Production sees new ids.

Deep explanation. Use behavior aggregates or a proper embedding with a rare-id bucket — not the integer id.

Common misconception. IDs are just numbers so the forest can split them.

Follow-up. What would you use instead for ‘this user churned last year’?

genaisafetyQ55

55. Who is allowed to see prompt logs?

Short answer. A small, audited group; redacted; short retention.

Deep explanation. Treat logs as production data. Vendor APM is another copy. Slack is not a store.

Common misconception. Engineers need raw everything to debug, forever.

Follow-up. How would you debug RAG without raw PII?

            Course topic. Foundations

            Language

            Glossary

            ACL

            Who may see which document or call which tool. Enforced in retrieval and code, not in the prompt.

            ANN

            Approximate nearest neighbor search over embeddings (HNSW, IVF). Fast, not exact.

            Baseline

            The simple system you beat: a rule, logistic regression, keyword search, or a prompt-only LLM.

            Chunking

            Splitting documents so retrieval can return a useful excerpt. Size is a product choice.

            Concept drift

            The meaning of the label changes (what counts as spam this year).

            Context window

            How many tokens the model can attend to in one call. Not a license to dump the wiki.

            Embedding

            A vector placed so similar items are nearby under cosine or dot product.

            Eval / golden set

            Versioned inputs with expected properties. Used like unit tests. Keep out of SFT train.

            Faithfulness

            Whether the answer is supported by the excerpts you retrieved — not whether it sounds smart.

            Fine-tuning / SFT

            Updating (some) weights on instruction or task pairs. For stable style or a narrow skill.

            FP / FN

            False positive vs false negative. Pick the metric from who pays for each.

            Injection (prompt)

            Untrusted text tries to override instructions or abuse tools. Delimit and least-privilege — do not study attack recipes here.

            Leakage

            Training on information that would not exist at prediction time. Inflates offline scores.

            LLM-as-judge

            Using a model to score answers. Fast, biased, must be calibrated to humans.

            LoRA

            Low-rank adapters: small trainable extra weights. Cheap to store and swap.

            Lost-in-the-middle

            Long prompts: models use the start and end more than the middle. Keep retrieved packs short.

            MLOps

            Versioning data, prompts, indexes, and models; CI eval; canary; rollback.

            Precision / recall

            Of what we flagged, how much was real / of what was real, how much we flagged.

            Preference / RLHF

            Training from ranked or preferred answers after SFT so the model is nicer or safer.

            Pretrain

            Next-token (or similar) training on a huge mix. You rarely rerun this as a product engineer.

            RAG

            Retrieve your text, generate from it, cite, refuse. Does not make the model universally truthful.

            Regularization

            Penalizing complexity (L2, dropout, early stop) so the model does not memorize noise.

            Rerank

            A second model that reorders the top retrieved chunks. Use when k is large or first-stage is noisy.

            Self-attention

            Each token mixes others, weighted by query–key similarity. Q looks, K is looked-up, V is mixed.

            Temperature

            How peaky next-token sampling is. Low for extract/JSON. Does not add facts.

            TTFT

            Time to first token. The ‘is it alive’ feeling. Stream to hide the rest of generation.

            Token

            A chunk of text the vendor counts. Roughly a few characters in English — measure, do not guess forever.
