The language

JS as a machine

DSA in JS is pointer-and-array thinking with a garbage collector. Learn the costs, then forget micro-optimizing V8.

Values, references, and why mutations surprise you

JavaScript values are either primitives (number, string, boolean, null, undefined, symbol, bigint) or objects (arrays, functions, maps, your nodes). Assignment of a primitive copies the value. Assignment of an object copies the reference — another arrow to the same box.

JavaScript
let a = 1;
let b = a;
b = 2;
// a is still 1

const x = { n: 1 };
const y = x;
y.n = 2;
// x.n is 2 — same object

function bump(obj) {
  obj.n += 1;          // mutates caller
  obj = { n: 0 };      // rebinds local only
}

This is why linked-list and tree code is “pointer” code even though JS has no *. A node is an object. curr.next = prev redirects an arrow.

stack (names) heap (objects) head ──────────────► { val: 1, next: ──► { val: 2, next: null } } curr ──────────────┘
Arrays are objects. const a = b does not copy elements. [...b] or b.slice() is a shallow copy — nested objects are still shared.

Big O

If n doubles, what happens?

Big O is how work grows, ignoring constants. Interviewers want you to read your loops.

ClassFeel when n doublesJS shape
O(1)sameindex, Map get
O(log n)one extra stepbinary search, balanced tree height
O(n)twice the workone for over n
O(n log n)~ sort-shapedarray.sort, many heap ops
O(n²)four timesnested loops both to n
O(2n)explodesunmemoized branching recursion
JavaScript
function sum(a) {           // O(n) time, O(1) extra space
  let s = 0;
  for (const x of a) s += x;
  return s;
}
function hasDupNaive(a) {   // O(n²)
  for (let i = 0; i < a.length; i++)
    for (let j = i + 1; j < a.length; j++)
      if (a[i] === a[j]) return true;
  return false;
}
function hasDup(a) {        // O(n) time, O(n) space
  const seen = new Set();
  for (const x of a) {
    if (seen.has(x)) return true;
    seen.add(x);
  }
  return false;
}

Space: extra arrays, maps, and recursion depth count. The input itself is usually not “extra.” Recursion depth of n is O(n) stack space.

n = 106. O(n) is fine. O(n log n) is usually fine. O(n²) is not. Say this out loud when you pick an approach.

The array is a numbered shelf

A JS array is an ordered list of slots 0..length-1. Index is O(1). Insert/delete at the front is O(n) because every index after the hole must move.

[ 10 | 20 | 30 | 40 ] 0 1 2 3 unshift(5) → move all right → O(n) push(50) → write at end → amortized O(1)
JavaScript
function indexOf(arr, target) {
  for (let i = 0; i < arr.length; i++) if (arr[i] === target) return i;
  return -1;
}

function reverseInPlace(arr) {
  let lo = 0, hi = arr.length - 1;
  while (lo < hi) {
    const t = arr[lo];
    arr[lo] = arr[hi];
    arr[hi] = t;
    lo++;
    hi--;
  }
  return arr;
}

function reverseRange(arr, lo, hi) {
  while (lo < hi) {
    [arr[lo], arr[hi]] = [arr[hi], arr[lo]];
    lo++;
    hi--;
  }
}

function rotateRight(arr, k) {
  const n = arr.length;
  if (!n) return arr;
  k %= n;
  reverseRange(arr, 0, n - 1);
  reverseRange(arr, 0, k - 1);
  reverseRange(arr, k, n - 1);
  return arr;
}

Two-array pattern: build out with push when you cannot mutate. In-place when the interviewer asks for O(1) extra space.

Holes: arr[100] = 1 on a short array makes a sparse array. Interview code should stay dense. Prefer push over assigning far indexes.

easyarrayone-pass scanTopic practice

1. Second largest

Return the second-largest distinct value, or null if it does not exist (all equal, or n < 2).

Idea. Track max and second. Only demote into second when x is strictly between them.

JavaScript
function secondLargest(a) {
  let max = -Infinity, second = -Infinity;
  for (const x of a) {
    if (x > max) { second = max; max = x; }
    else if (x < max && x > second) second = x;
  }
  return second === -Infinity ? null : second;
}

Time. O(n)   Space. O(1)

Why this works. Sorting the array just to read the top two values costs O(n log n) and still fails when duplicates hide the true second place. A single left-to-right scan keeps two running bests and updates them in constant time per element.

Step by step.

  1. Initialize max_val and second to negative infinity (or null).
  2. For each x, if x beats max_val, slide old max into second, then set max_val = x.
  3. Else if x is strictly greater than second but not max_val, set second = x.
  4. After the loop, return second only if it was ever updated from its sentinel.

Trace.

nums = [3, 1, 4, 4, 2] scan: 3 -> max=3 1 -> second=1 4 -> second=3, max=4 4 -> skip (not strictly between) 2 -> second=3 output: 3

Watch. Treating a duplicate of the maximum as the second largest is wrong — second must be a strictly smaller distinct value.

Complexity. Time O(n). Extra space O(1).

easyarraywrite pointerTopic practice

2. Move zeros to the end

Mutate nums so all zeros sit at the end. Relative order of non-zeros stays. Extra array is legal only if you then copy back — prefer one write index.

Idea. Read pointer scans. Write index takes the next non-zero. Fill the tail with zeros.

JavaScript
function moveZeroes(nums) {
  let w = 0;
  for (let r = 0; r < nums.length; r++) if (nums[r] !== 0) nums[w++] = nums[r];
  while (w < nums.length) nums[w++] = 0;
  return nums;
}

Time. O(n)   Space. O(1)

Why this works. Copying non-zeros into a fresh array works but wastes space and needs a copy-back pass. One read pointer and one write pointer move each non-zero exactly once, preserving order in O(n) time with O(1) extra memory.

Step by step.

  1. Set write = 0 and read = 0.
  2. While read < n, if nums[read] != 0, assign nums[write] = nums[read] and increment write.
  3. Always increment read.
  4. After the scan, fill indices write..n-1 with zeros.

Trace.

nums = [0, 1, 0, 3, 12] read/write trace: r0: skip 0 r1: write[0]=1 w=1 r2: skip 0 r3: write[1]=3 w=2 r4: write[2]=12 w=3 tail fill: [1,3,12,0,0,0] output: [1, 3, 12, 0, 0]

Watch. Forgetting to zero the tail after compaction leaves stale values past the write index.

Complexity. Time O(n). Extra space O(1).

easyarrayprefix in placeTopic practice

3. Running sum

Return the prefix sums: out[i] = nums[0] + … + nums[i]. Mutate or allocate — say which.

Idea. Keep a running total. Each slot is previous total + this value.

JavaScript
function runningSum(nums) {
  for (let i = 1; i < nums.length; i++) nums[i] += nums[i - 1];
  return nums;
}

Time. O(n)   Space. O(1) extra

Why this works. Re-summing from index 0 on every position repeats work and becomes O(n squared). Each prefix is just the previous prefix plus the current number, so one pass builds the entire answer.

Step by step.

  1. If mutating in place, nums[0] is already the first prefix.
  2. Set running = nums[0] (or 0 before the loop if using a new array).
  3. For i from 1 to n-1, add nums[i] to running and store at out[i].
  4. Return the array (same reference if in-place).

Trace.

nums = [1, 2, 3, 4] i=0: running=1 out=[1,_,_,_] i=1: running=3 out=[1,3,_,_] i=2: running=6 out=[1,3,6,_] i=3: running=10 out=[1,3,6,10] output: [1, 3, 6, 10]

Watch. Starting running at 0 when overwriting nums[0] in place loses the first element.

Complexity. Time O(n). Extra space O(1) extra.

easyarraydigits / carryTopic practice

4. Plus one

digits is a non-negative integer, most significant digit first. Add one and return the new digit array.

Idea. Walk from the end. 9 becomes 0 and carry continues. If you leave the loop still carrying, unshift 1.

JavaScript
function plusOne(digits) {
  for (let i = digits.length - 1; i >= 0; i--) {
    if (digits[i] < 9) { digits[i]++; return digits; }
    digits[i] = 0;
  }
  digits.unshift(1);
  return digits;
}

Time. O(n)   Space. O(1) extra (unshift is O(n) once)

Why this works. Converting the digit array to a number and back breaks on large inputs and ignores the carry structure. Walking from the least significant digit mirrors grade-school addition and handles overflow with at most one extra digit.

Step by step.

  1. Start at the last index with carry = 1.
  2. While carry > 0 and index >= 0, add carry to digits[i], set carry = digit // 10, digit %= 10.
  3. Store the reduced digit and move left.
  4. If carry remains after the loop, prepend 1 to the array.

Trace.

digits = [1, 2, 9] i=2: 9+1=10 -> digit=0, carry=1 i=1: 2+1=3 -> digit=3, carry=0 done output: [1, 3, 0]

Watch. Using unshift in a loop is O(n) per call — prepend once at the end or build reversed.

Complexity. Time O(n). Extra space O(1) extra (unshift is O(n) once).

easyarrayindex as markTopic practice

5. All disappeared numbers

nums contains n integers, each in 1..n. Some values are missing (others repeat). Return every missing value. O(n) time, O(1) extra besides the answer.

Idea. Mark presence by negating nums[abs(x)-1]. A still-positive slot i means i+1 never appeared.

JavaScript
function findDisappeared(nums) {
  for (const x of nums) {
    const i = Math.abs(x) - 1;
    if (nums[i] > 0) nums[i] = -nums[i];
  }
  const out = [];
  for (let i = 0; i < nums.length; i++) if (nums[i] > 0) out.push(i + 1);
  return out;
}

Time. O(n)   Space. O(1) extra

Why this works. A hash set of seen values uses extra O(n) space. Because every value lies in 1..n, you can use the array itself as a bitmap by flipping signs at corresponding indices.

Step by step.

  1. For each x, let idx = abs(x) - 1.
  2. If nums[idx] is already negative, x is a duplicate — continue.
  3. Otherwise negate nums[idx] to mark x as present.
  4. Scan i from 0..n-1; if nums[i] > 0, push i+1 into the answer.

Trace.

nums = [4, 3, 2, 7, 8, 2, 3, 1] mark via negation at indices 3,2,1,6,7,... positive slots: index 4 (5), index 5 (6) output: [5, 6]

Watch. Using x instead of abs(x) when the array already has negative marks sends you to the wrong index.

Complexity. Time O(n). Extra space O(1) extra.

easyarrayrun lengthTopic practice

6. Max consecutive ones

Binary array. Length of the longest run of 1s.

Idea. Reset the run on 0. Track the best run.

JavaScript
function findMaxConsecutiveOnes(nums) {
  let run = 0, best = 0;
  for (const x of nums) {
    run = x === 1 ? run + 1 : 0;
    best = Math.max(best, run);
  }
  return best;
}

Time. O(n)   Space. O(1)

Why this works. Counting all ones globally misses the longest contiguous block. Track the current streak and reset it on zero — one pass, constant extra space.

Step by step.

  1. Set best = 0 and cur = 0.
  2. For each bit, if 1 then cur += 1 else cur = 0.
  3. After each update, best = max(best, cur).
  4. Return best.

Trace.

nums = [1,1,0,1,1,1,0] cur: 1,2,0,1,2,3,0 best peaks at 3 output: 3

Watch. Updating best only at the end of a run misses a run that ends at the last index.

Complexity. Time O(n). Extra space O(1).

easyarrayfill from the backTopic practice

7. Merge into a buffer

nums1 has length m+n: first m values sorted, last n are unused 0s. nums2 is n sorted values. Merge nums2 into nums1 in-place, sorted.

Idea. Three pointers from the tails. The largest leftover writes at the end so you do not overwrite unread values.

JavaScript
function merge(nums1, m, nums2, n) {
  let i = m - 1, j = n - 1, w = m + n - 1;
  while (j >= 0) {
    if (i >= 0 && nums1[i] > nums2[j]) nums1[w--] = nums1[i--];
    else nums1[w--] = nums2[j--];
  }
  return nums1;
}

Time. O(m+n)   Space. O(1)

Why this works. Merging forward overwrites unread elements in nums1. Writing the largest remaining value from the back never clobbers data you still need.

Step by step.

  1. Set i = m-1, j = n-1, write = m+n-1.
  2. While both i and j are valid, place the larger of nums1[i] and nums2[j] at write and decrement pointers.
  3. Drain whichever side has leftovers into the front portion.
  4. nums1 is sorted in place; no return value needed beyond mutation.

Trace.

nums1=[1,2,3,0,0,0] m=3 nums2=[2,5,6] n=3 write: 6,5,3,2,2,1 output: [1,2,2,3,5,6]

Watch. Starting write at m instead of m+n-1 writes into the empty tail incorrectly.

Complexity. Time O(m+n). Extra space O(1).

easyarrayBoyer–MooreTopic practice

8. Majority element

An element appears more than n/2 times. Return it. Follow-up: O(1) extra, one pass.

Idea. Candidate + count. Matching increments, mismatch decrements, count 0 picks a new candidate. The majority always survives.

JavaScript
function majorityElement(nums) {
  let cand = null, count = 0;
  for (const x of nums) {
    if (count === 0) cand = x;
    count += x === cand ? 1 : -1;
  }
  return cand;
}

Time. O(n)   Space. O(1)

Why this works. Sorting or hashing counts works but costs extra time or space. Boyer-Moore voting cancels minority votes against the majority in one pass because the true majority always outnumbers everything else combined.

Step by step.

  1. Set candidate = nums[0] and count = 1.
  2. For each x after the first, if count is 0 set candidate = x and count = 1.
  3. Else if x == candidate increment count, else decrement count.
  4. Return candidate (valid when majority is guaranteed).

Trace.

nums = [2, 2, 1, 1, 1, 2, 2] cand: 2->2->1->1->1->2->2 count swings but 2 survives output: 2

Watch. Without a guaranteed majority you must verify the candidate with a second pass.

Complexity. Time O(n). Extra space O(1).

mediumarraythree-way partitionTopic practice

9. Sort colors (Dutch flag)

Array of 0, 1, 2 only. Sort in-place in one pass. No library sort.

Idea. lo writes the next 0, hi the next 2, i scans. Swap 0 left, 2 right, stay on 2 because the inbound value is unknown.

JavaScript
function sortColors(a) {
  let lo = 0, i = 0, hi = a.length - 1;
  while (i <= hi) {
    if (a[i] === 0) { [a[lo], a[i]] = [a[i], a[lo]]; lo++; i++; }
    else if (a[i] === 2) { [a[hi], a[i]] = [a[i], a[hi]]; hi--; }
    else i++;
  }
  return a;
}

Time. O(n)   Space. O(1)

Why this works. Counting sort with three buckets needs two passes and extra arrays. Dutch national flag partitioning swaps 0s left and 2s right while scanning once, keeping 1s in the middle automatically.

Step by step.

  1. Set lo = 0, hi = n-1, i = 0.
  2. While i <= hi, if nums[i] == 0 swap with lo and increment both lo and i.
  3. If nums[i] == 2 swap with hi and decrement hi (do not advance i).
  4. If nums[i] == 1 increment i only.

Trace.

nums = [2,0,2,1,1,0] lo/i/hi dance -> [0,0,1,1,2,2] output: [0, 0, 1, 1, 2, 2]

Watch. Advancing i after swapping a 2 inward can skip an unclassified value pulled from the right.

Complexity. Time O(n). Extra space O(1).

easyarrayprefix vs suffixTopic practice

10. Pivot index

Index i where sum(left of i) === sum(right of i). Return the leftmost, or -1.

Idea. Total sum once. Walk left-sum. Right = total - left - a[i].

JavaScript
function pivotIndex(a) {
  const total = a.reduce((s, x) => s + x, 0);
  let left = 0;
  for (let i = 0; i < a.length; i++) {
    if (left === total - left - a[i]) return i;
    left += a[i];
  }
  return -1;
}

Time. O(n)   Space. O(1)

Why this works. Recomputing left and right sums at every index is quadratic. One total plus a running left sum gives the right side by subtraction in O(1) per index.

Step by step.

  1. Compute total = sum(nums).
  2. Set left = 0.
  3. For each i, right = total - left - nums[i].
  4. If left == right return i; else left += nums[i].
  5. Return -1 if none match.

Trace.

nums = [1, 7, 3, 6, 5, 6] total=28 i=3: left=11 right=11 -> pivot 3 output: 3

Watch. Including nums[i] in the left sum before checking makes the balance wrong by one element.

Complexity. Time O(n). Extra space O(1).

Strings are immutable sequences

You cannot assign s[i] = 'x' and have it stick. Build a new string or use an array of characters. For interviews, convert with s.split('') when you need random access writes — know that is extra O(n) space.

JavaScript
function isPalindrome(s) {
  const t = s.toLowerCase().replace(/[^a-z0-9]/g, "");
  let lo = 0, hi = t.length - 1;
  while (lo < hi) {
    if (t[lo] !== t[hi]) return false;
    lo++;
    hi--;
  }
  return true;
}

function reverseWords(s) {
  return s.trim().split(/\s+/).reverse().join(" ");
}

Code units: s.length and s[i] are UTF-16 units. Emoji can be two units. For interview ASCII problems this is fine; for real i18n use [...s] or Intl.

easystringtwo pointersTopic practice

1. Reverse a character array

s is an array of characters. Reverse it in place.

Idea. Swap from the ends inward. Do not build a new string in a loop.

JavaScript
function reverseString(s) {
  let lo = 0, hi = s.length - 1;
  while (lo < hi) { [s[lo], s[hi]] = [s[hi], s[lo]]; lo++; hi--; }
  return s;
}

Time. O(n)   Space. O(1)

Why this works. Building a reversed copy character by character uses O(n) extra space. Swapping symmetric pairs from both ends finishes in place with half as many writes.

Step by step.

  1. Set left = 0 and right = len(s) - 1.
  2. While left < right, swap s[left] and s[right].
  3. Increment left and decrement right.
  4. Stop when pointers meet or cross.

Trace.

s = ['h','e','l','l','o'] swap 0<->4 -> ['o','e','l','l','h'] swap 1<->3 -> ['o','l','l','e','h'] output: olleh

Watch. Using <= instead of < causes the middle character to swap with itself unnecessarily on odd lengths.

Complexity. Time O(n). Extra space O(1).

easystringscan columnsTopic practice

2. Longest common prefix

Array of strings. Longest prefix shared by every string, or "".

Idea. Walk character columns of the first word. Stop at the first mismatch or short word.

JavaScript
function longestCommonPrefix(strs) {
  if (!strs.length) return "";
  for (let i = 0; i < strs[0].length; i++) {
    const ch = strs[0][i];
    for (let k = 1; k < strs.length; k++) if (strs[k][i] !== ch) return strs[0].slice(0, i);
  }
  return strs[0];
}

Time. O(total chars)   Space. O(1)

Why this works. Comparing every pair of strings blows up to O(n^2 * m). Scanning column by column against the shortest word stops at the first mismatch shared by all.

Step by step.

  1. If the array is empty return empty string.
  2. Use the first string as reference length (or min length across all).
  3. For column c from 0 while c < minLen, compare every string's char at c.
  4. On mismatch return s[0..c-1]; if all columns match return that prefix.

Trace.

strs = ["flower","flow","flight"] col0: f f f ok col1: l l l ok col2: o o i stop output: "fl"

Watch. Assuming the first string is the shortest — a later string may end early and break the prefix.

Complexity. Time O(total chars). Extra space O(1).

3. String compression

chars is a char array. Compress in-place: a,a,a,b,b → a,3,b,2. Return the new length. Groups of 1 stay a single letter.

Idea. Read runs. Write the letter, then the digits of the count if count > 1.

JavaScript
function compress(chars) {
  let w = 0, r = 0;
  while (r < chars.length) {

  return w;
}

Time. O(n)   Space. O(1) extra

  2. While read < n, record the char and count the run length.
  3. Write the char at write, advance write.
  4. If count > 1, write each decimal digit of count.
  5. Advance read past the entire run.
  6. Return write as the new logical length.

    const node = new ListNode(val);

    let t = this.head;
    while (t.next) t = t.next;

Why this works. Each digit maps to several letters, so the output size is the product of those choices. Recursion walks one digit at a time and tries every letter for that digit. That systematically enumerates all combinations without nested loops of unknown depth.

Step by step.

  1. Build a map from digit char to its letter string (skip '0' and '1').
  2. Start DFS at index 0 with an empty path string.
  3. At index i, loop each letter of map[digits[i]], append, recurse to i+1, then pop.
  4. When i == len(digits), push path to answers.
  5. Return early if digits is empty.

4. Max depth of nested arrays

Nested number arrays, e.g. [1,[2,[3]]]. Depth of the deepest nest (that example is 3).

Idea. A number is depth 1 if you count the current box, or 0 if you only count arrays — pick one and be consistent. Here: empty array is 1, number does not add a level beyond its container.

JavaScript
function arrayDepth(x) {
  if (!Array.isArray(x)) return 0;
  if (!x.length) return 1;
  return 1 + Math.max(0, ...x.map(arrayDepth));
}

Time. O(nodes)   Space. O(depth)

Why this works. Nested arrays form a tree: each inner array is a child. The depth of the whole structure is one plus the max depth among its children. A single DFS pass computes this without flattening or counting brackets manually.

Step by step.

  1. Define depth(arr): if arr is not a list, return 0 (or 1 if counting the leaf box).
  2. If arr is empty, return 1 for 'current box counts'.
  3. For each element, take max depth among children.
  4. Return 1 + that max.
  5. Call depth on the top-level input.

Trace.

Input: [1, [2, [3]]] depth([3]) -> 1 (single number inside) depth([2,[3]]) -> 1 + max(0,1) = 2 depth(top) -> 1 + max(0,2) = 3 Output: 3

Watch. Mixing conventions: counting only arrays vs counting the outermost wrapper. Empty array [] is depth 1 under the usual 'box counts' rule, not 0.

Complexity. Time O(nodes). Extra space O(depth).

5. Fibonacci with memo

Return F(n) with F(0)=0, F(1)=1. Must be O(n), not the naive tree.

Idea. Map or array cache. This is DP in recursive clothes.

JavaScript
function fib(n, memo = new Map([[0, 0], [1, 1]])) {
  if (memo.has(n)) return memo.get(n);
  const v = fib(n - 1, memo) + fib(n - 2, memo);
  memo.set(n, v);
  return v;
}

Time. O(n)   Space. O(n)

Why this works. Plain recursion recomputes the same F(k) many times, exploding to exponential time. Memoization stores each answer the first time it is computed. Every later call becomes O(1) lookup, giving O(n) total work.

Step by step.

  1. Base cases: F(0)=0, F(1)=1.
  2. If n is in the cache, return cache[n].
  3. Otherwise set cache[n] = F(n-1) + F(n-2).
  4. Return cache[n].
  5. An iterative loop with two rolling variables is equivalent and avoids stack depth.

Trace.

Input: n=5 F(2)=1, F(3)=2, F(4)=3, F(5)=5 cache after: {0:0, 1:1, 2:1, 3:2, 4:3, 5:5} Output: 5

6. K-th symbol in grammar

Row 1 is 0. Each 0 becomes 01, each 1 becomes 10. Return the k-th (1-based) bit in row n.

Idea. Row n has 2^(n-1) bits. The second half is the first half flipped. Recurse into the half that contains k.

JavaScript
function kthGrammar(n, k) {
  if (n === 1) return 0;
  const half = 1 << (n - 2);
  if (k <= half) return kthGrammar(n - 1, k);
  return 1 - kthGrammar(n - 1, k - half);
}

Time. O(n)   Space. O(n)

Why this works. Building row n literally doubles in size every step, so materializing it is impossible for large n. Row n has 2^(n-1) bits and the second half is the bitwise flip of the first half. You can decide which half contains index k and recurse without ever storing the row.

Step by step.

  1. Base: row 1 is just the bit 0.
  2. Let half = 2^(n-2); if k > half, answer is flip of kthSymbol(n-1, k-half).
  3. If k <= half, answer equals kthSymbol(n-1, k).
  4. Flip means 0->1 and 1->0.
  5. Use 1-based k throughout.

Trace.

Input: n=3, k=3 row3 length 4; k=3 is in second half of row3 flip( kthSymbol(2, 1) ) row2 = 01; k=1 -> 0 flip(0) = 1 Output: 1

Watch. Using 0-based k or comparing k to the wrong half size (off by one power of two). Forgetting to flip when k lands in the second half.

Complexity. Time O(n). Extra space O(n).

Swap every left/right pair. Return the root.

Idea. Recurse both sides, then swap — or swap then recurse. Same work.

function invertTree(root) {

}

  2. Recursively invert left and right subtrees.

2. Symmetric tree

True if the tree is a mirror of itself.

Idea. Helper(a,b): both null, or vals equal and a.left mirrors b.right and a.right mirrors b.left.

JavaScript
function isSymmetric(root) {
  function same(a, b) {
    if (!a || !b) return a === b;
    return a.val === b.val && same(a.left, b.right) && same(a.right, b.left);
  }
  return same(root, root);
}

Time. O(n)   Space. O(h)

Why this works. Symmetry is not about comparing a node to itself but about mirror pairs across the center. Left of one side must match right of the other with equal values. A helper that takes two nodes reduces the problem to simple null and value checks.

Step by step.

  1. Define mirror(a, b): if both null, true; if one null, false.
  2. If a.val != b.val, return false.
  3. Return mirror(a.left, b.right) and mirror(a.right, b.left).
  4. Answer is mirror(root.left, root.right).
  5. Empty tree is symmetric.

Trace.

Input: 1 / \ 2 2 / \ / \ 3 4 4 3 mirror(2,2): vals ok; mirror(3,3) and mirror(4,4) both true Output: true

Watch. Only comparing inorder or only checking root.left.val == root.right.val misses deeper asymmetry.

Complexity. Time O(n). Extra space O(h).

3. Path sum

True if a root-to-leaf path sums to target.

Idea. At a leaf, check val === remain. Else try children with remain - val.

JavaScript
function hasPathSum(root, target) {
  if (!root) return false;
  if (!root.left && !root.right) return root.val === target;

}

Time. O(n)   Space. O(h)

Why this works. You do not need to store paths; subtract each node value from the target as you walk down. At a leaf, whatever remains must be exactly zero. That turns path search into a single downward pass with O(h) stack space.

Step by step.

  1. If root is null, return false.
  2. Compute remain = target - root.val.
  3. If root is a leaf, return remain == 0.
  4. Return hasPathSum(left, remain) or hasPathSum(right, remain).
  5. Do not treat a single-child node as a leaf unless it has no children.

4. Diameter

Longest number of edges on any path (need not pass through the root).

Idea. Height function returns height and updates a global best = leftH + rightH.

JavaScript
function diameterOfBinaryTree(root) {
  let best = 0;
  function h(n) {
    if (!n) return 0;
    const L = h(n.left), R = h(n.right);
    best = Math.max(best, L + R);
    return 1 + Math.max(L, R);
  }
  h(root);
  return best;
}

Time. O(n)   Space. O(h)

Why this works. The longest path may not go through the root, so a global best tracker is needed. At each node, the best path through that node is leftHeight + rightHeight. Computing height bottom-up gives both pieces in one DFS.

Step by step.

  1. Keep a global best = 0 (edge count).
  2. height(node): if null, return 0.
  3. leftH = height(node.left), rightH = height(node.right).
  4. best = max(best, leftH + rightH).
  5. Return 1 + max(leftH, rightH) to parent.

Trace.

Input: 1 / \ 2 3 / \ 4 5 At node 2: leftH=1, rightH=1 -> through-2 diameter=2 At node 1: leftH=2, rightH=1 -> through-1 diameter=3 Output: 3 edges (path 4-2-1-3 or 5-2-1-3)

5. LCA in a binary tree

Lowest common ancestor of p and q in a general binary tree (not necessarily BST).

Idea. If root is null/p/q, return root. If both sides return non-null, root is LCA. Else bubble the non-null.

function lowestCommonAncestor(root, p, q) {
  if (!root || root === p || root === q) return root;
  const L = lowestCommonAncestor(root.left, p, q);
  const R = lowestCommonAncestor(root.right, p, q);
  return L && R ? root : L || R;
}

Time. O(n)   Space. O(h)

Why this works. In a general binary tree the LCA is the deepest node where p and q diverge into different subtrees. Post-order search tells you whether each side contains p or q. The first node that gets non-null from both sides is the answer.

Step by step.

  1. If root is null or root is p or q, return root.
  2. left = search(root.left), right = search(root.right).
  3. If both left and right are non-null, root is the LCA.
  4. Otherwise return whichever side is non-null.
  5. Works for general binary trees, not only BSTs.

6. Count good nodes

A node is good if it is the maximum on the path from the root to itself. Count them.

Idea. DFS with maxSoFar. If node.val >= maxSoFar, count 1.

    if (!n) return 0;
    const good = n.val >= mx ? 1 : 0;
    const next = Math.max(mx, n.val);
    return good + go(n.left, next) + go(n.right, next);
  }
  return go(root, -Infinity);
}

Time. O(n)   Space. O(h)

Why this works. A node is good if no ancestor has a larger value, so you only need the max seen so far on the path. Pass that max down during DFS and increment when node.val >= maxSoFar. No need to compare against all ancestors each time.

Step by step.

  1. DFS(node, maxSoFar): if null, return 0.
  2. If node.val >= maxSoFar, count = 1; else 0.
  3. newMax = max(maxSoFar, node.val).
  4. Return count + DFS(left, newMax) + DFS(right, newMax).
  5. Start with maxSoFar = -infinity (or root.val handled separately).

7. Right side view

Values you see standing on the right, top to bottom.

Idea. BFS. The last node in each level is visible. DFS: visit right first and record the first visit at each depth.

8. Flatten to a linked list

Flatten the tree into a right-skewed list in preorder. left must become null. Do it in place.

Idea. Recurse right, then left. A trailing prev pointer: node.right = prev; node.left = null; prev = node. Walk from the right.

function flatten(root) {

    go(n.right); go(n.left);

}

9. Kth smallest in a BST

1-based k. BST inorder is sorted.

Idea. Iterative inorder, decrement k on each pop. When k hits 0, that node is the answer.

function kthSmallest(root, k) {
  const st = [];
  let n = root;
  while (st.length || n) {
    while (n) { st.push(n); n = n.left; }
    n = st.pop();
    if (--k === 0) return n.val;
    n = n.right;
  }
}

Time. O(h+k)   Space. O(h)

Why this works. BST inorder visits values in sorted order, so the k-th pop is the k-th smallest. Iterative inorder avoids recursion depth and lets you stop early at k. That is O(h + k) instead of sorting all nodes.

Step by step.

  1. Stack = [], cur = root.
  2. While stack or cur: go left pushing nodes, then pop.
  3. On each pop, decrement k; when k == 0, return that node.val.
  4. Move cur to popped.right and continue.
  5. No need to traverse the whole tree once k hits zero.

A heap is a complete tree stored in an array

class MinHeap {
  constructor() { this.a = []; }
  peek() { return this.a[0]; }
  push(x) {
    this.a.push(x);
    this._up(this.a.length - 1);
  }
  pop() {
    const a = this.a;
    if (a.length === 0) return undefined;
    const top = a[0];
    const last = a.pop();
    if (a.length) { a[0] = last; this._down(0); }
    return top;
  }
  _up(i) {
    const a = this.a;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (a[p] <= a[i]) break;
      [a[p], a[i]] = [a[i], a[p]];
      i = p;
    }
  }
  _down(i) {
    const a = this.a, n = a.length;
    while (true) {
      let s = i, l = i * 2 + 1, r = l + 1;
      if (l < n && a[l] < a[s]) s = l;
      if (r < n && a[r] < a[s]) s = r;
      if (s === i) break;
      [a[s], a[i]] = [a[i], a[s]];
      i = s;
    }
  }
}

function topK(nums, k) {
  const h = new MinHeap();
  for (const x of nums) {
    h.push(x);
    if (h.a.length > k) h.pop();
  }
  return h.a.slice();
}

1. Last stone weight

Smash the two heaviest. If unequal, push the difference. Last stone (or 0).

Idea. Max-heap (negate in a min-heap, or sort each time for n≤30). Pop two, push |a-b| if nonzero.

function lastStoneWeight(stones) {
  const h = stones.slice().sort((a, b) => a - b);
  while (h.length > 1) {
    const a = h.pop(), b = h.pop();
    if (a !== b) {
      h.push(a - b);
      h.sort((x, y) => x - y);
    }
  }
  return h[0] || 0;
}

Step by step.

  1. Push all weights into a max-heap (negate for a min-heap in Python).
  2. While more than one stone remains, pop two largest a and b.
  3. If a != b, push a - b back.
  4. Return the last stone or 0 if empty.
  5. Each smash is at most two pops and maybe one push.

3. Kth largest with a min-heap

Kth largest in an unsorted array. Use a min-heap of size k (do not only sort).

Idea. Push; if size > k, pop. The root is the answer.

JavaScript
function findKthLargest(nums, k) {
  const h = [];
  const up = (i) => { while (i) { const p = (i-1)>>1; if (h[p] <= h[i]) break; [h[p],h[i]]=[h[i],h[p]]; i=p; } };
  const down = (i) => { for (;;) { let s=i,l=2*i+1,r=l+1; if (l<h.length && h[l]<h[s]) s=l; if (r<h.length && h[r]<h[s]) s=r; if (s===i) break; [h[s],h[i]]=[h[i],h[s]]; i=s; } };
  for (const x of nums) {
    h.push(x); up(h.length-1);
    if (h.length > k) { h[0] = h.pop(); if (h.length) down(0); }
  }
  return h[0];
}

Time. O(n log k)   Space. O(k)

Why this works. The k largest elements are exactly the ones that survive if you only ever drop the smallest among a size-k window. A min-heap of size k keeps that window: its root is the k-th largest overall. One pass beats sorting when k is much smaller than n.

Step by step.

  1. Push each num into a min-heap.
  2. Whenever size exceeds k, pop the smallest.
  3. After scanning all nums, heap[0] is the k-th largest.
  4. Do not pop down to empty; stop when size equals k.
  5. For duplicates, heap semantics still hold.

Trace.

5. Sort a k-sorted array

Every element is at most k positions from its sorted index. Sort in better than n log n when k ≪ n.

Idea. Min-heap of the first k+1 values. Pop into the write index, push the next.

JavaScript
function sortKSorted(a, k) {
  const h = a.slice(0, k + 1).sort((x, y) => x - y);
  const out = [];
  for (let i = k + 1; i < a.length; i++) {
    out.push(h.shift());
    h.push(a[i]);
    h.sort((x, y) => x - y);
  }
  while (h.length) out.push(h.shift());
  return out;
}

Time. O(n log k) with a heap   Space. O(k)

Why this works. Each position's true value lies within k slots ahead in the sorted order, so a sliding window of k+1 elements always contains the next output. A min-heap extracts the smallest in that window in O(log k) time. When k is tiny this beats O(n log n) full sort.

Step by step.

  1. Push the first min(k+1, n) elements into a min-heap.
  2. For i from 0 to n-1: pop heap min into arr[i].
  3. If i+k+1 < n, push arr[i+k+1] into the heap.
  4. Heap never holds more than k+1 items.
  5. Array becomes sorted in place logically via write index.

Trace.

Input: arr=[6,5,3,2,8,10,9,1], k=2 Window heap min writes: 2,3,5,6,8,9,10,1 -> sorted Output: [1,2,3,5,6,8,9,10]

6. Median of a stream

addNum and findMedian. Median is middle or average of two middles.

Idea. Max-heap for the lower half, min-heap for the upper. Sizes differ by at most 1. Rebalance after each insert.

JavaScript
class MedianFinder {
  constructor() { this.lo = []; this.hi = []; } // lo max via negate, hi min — here we sort for the idea
  addNum(x) {
    this.lo.push(x); this.lo.sort((a, b) => a - b);
    this.hi.push(this.lo.pop()); this.hi.sort((a, b) => a - b);
    if (this.hi.length > this.lo.length) this.lo.push(this.hi.shift());
    this.lo.sort((a, b) => a - b);
  }
  findMedian() {
    if (this.lo.length > this.hi.length) return this.lo[this.lo.length - 1];
    return (this.lo[this.lo.length - 1] + this.hi[0]) / 2;
  }
}
// Real answer: binary heaps, not sort. This is the split invariant.

Time. O(log n) with heaps   Space. O(n)

Why this works. The median splits the stream into a lower and upper half. Two heaps keep the lower half in a max-heap and the upper in a min-heap so the tops meet in the middle. Rebalancing after each insert gives O(log n) add and O(1) median read.

Step by step.

  1. low = max-heap (negate in Python), high = min-heap.
  2. On addNum(x): push to low first, then balance.
  3. Move low's max to high if low is bigger; if high is larger than low by more than 1, move high's min to low.
  4. findMedian: if equal sizes, average both tops; else top of the larger heap.
  5. Keep size difference at most 1.

Trace.

Input: add 1, add 2, findMedian, add 3, findMedian After 1,2: low=[1], high=[2] -> median 1.5 After 3: low=[2], high=[3] or low=[1,2] high=[3] balanced -> median 2 Output: 1.5 then 2.0

Watch. Putting all values in one heap forces O(n) median reads. Wrong rebalance rule lets one heap outgrow the other by 2+ and picks the wrong middle.

Idea. Enqueue every rotten at minute 0. BFS. Count fresh; fail if leftover.

function orangesRotting(grid) {
  const R = grid.length, C = grid[0].length, q = [];
  let fresh = 0, minutes = 0;
  for (let r=0;r<R;r++) for (let c=0;c<C;c++) {
    if (grid[r][c]===2) q.push([r,c,0]);
    if (grid[r][c]===1) fresh++;
  }
  const dirs = [[1,0],[-1,0],[0,1],[0,-1]];
  for (let i = 0; i < q.length; i++) {
    const [r,c,d] = q[i];
    minutes = d;
    for (const [dr,dc] of dirs) {
      const nr=r+dr, nc=c+dc;
      if (nr<0||nc<0||nr>=R||nc>=C||grid[nr][nc]!==1) continue;
      grid[nr][nc]=2; fresh--; q.push([nr,nc,d+1]);
    }
  }
  return fresh ? -1 : minutes;
}

Step by step.

  1. Count fresh; enqueue all (r,c) with value 2 at minute 0.

function shortestPathBinaryMatrix(g) {

  const q = [[0,0,1]]; g[0][0] = 1;

  3. Dequeue, if at [n-1,n-1] return length.

  5. If queue empties, return -1.

4. Minimum window substring

Smallest substring of s that covers every char of t (including duplicates). "" if impossible.

Idea. Need map + missing count. Grow right. When missing is 0, shrink left and record best.

function minWindow(s, t) {
  const need = new Map();
  for (const ch of t) need.set(ch, (need.get(ch) || 0) + 1);
  let missing = t.length, best = "", bestLen = Infinity, left = 0;
  for (let r = 0; r < s.length; r++) {
    if (need.has(s[r])) {
      if (need.get(s[r]) > 0) missing--;
      need.set(s[r], need.get(s[r]) - 1);
    }
    while (!missing) {
      if (r - left + 1 < bestLen) { bestLen = r - left + 1; best = s.slice(left, r + 1); }
      if (need.has(s[left])) {
        need.set(s[left], need.get(s[left]) + 1);
        if (need.get(s[left]) > 0) missing++;
      }
      left++;
    }
  }
  return best;
}

Time. O(n)   Space. O(alphabet)

Why this works. Expand until all required characters are covered, then shrink from the left to minimize length while coverage holds. Missing count tells you when the window is valid.

Step by step.

  1. Build need map for t and missing = distinct required chars not yet satisfied.
  2. Expand right, decrement missing when a needed char hits zero surplus.
  3. When missing == 0, update best and shrink left while still valid.
  4. On shrink, increment missing if a needed char becomes deficient.
  5. Return best window or empty string.

Trace.

s = "ADOBECODEBANC", t = "ABC" grow until A,B,C covered at "ADOBEC" shrink: "DOBEC" still covers -> "BEC" ... best "BANC" output: "BANC"

Watch. Shrinking before missing hits zero, or using unique char count instead of duplicate-aware need counts, drops required letters.

Complexity. Time O(n). Extra space O(alphabet).

  5. Return dp[target].

Trace.

nums = [1, 5, 11, 5] sum=22 target=11 can pick 1+5+5=11 output: true

Watch. Looping sums upward lets the same coin be reused like unbounded knapsack. Inner loop must go backward for 0/1 use-once.

Complexity. Time O(n · sum). Extra space O(sum).

5. Longest palindromic substring

Return one longest palindromic substring of s. Expand-around-center is enough; DP table is the other write-up.

Idea. For each index, expand odd and even radii. Track the best start/len.

JavaScript
function longestPalindrome(s) {
  let start = 0, best = 1;
  function exp(lo, hi) {
    while (lo >= 0 && hi < s.length && s[lo] === s[hi]) { lo--; hi++; }
    if (hi - lo - 1 > best) { start = lo + 1; best = hi - lo - 1; }
  }
  for (let i = 0; i < s.length; i++) { exp(i, i); exp(i, i + 1); }
  return s.slice(start, start + best);
}

Time. O(n²)   Space. O(1)

Why this works. Every palindrome has a center. Expanding outward from each center finds the longest palindrome in O(n^2) without a full n^2 DP table, since mirroring checks are local.

Step by step.

  1. Track best start and length.
  2. For each index i, expand odd center at i.
  3. Expand even center between i and i+1.
  4. While in bounds and chars match, expand lo/hi.
  5. Update best when new length exceeds old.

Trace.

s = "babad" center at 1 ('a'): expands "aba" len 3 center at 2: "bab" len 3 output: "bab" or "aba"

Watch. Only checking odd centers misses even-length palindromes like "bb". Always run both expansions.

Complexity. Time O(n²). Extra space O(1).

6. Jump game

Each value is a max jump length. True if you can reach the last index.

Idea. Greedy farthest: while i ≤ farthest, farthest = max(farthest, i+a[i]). True if farthest reaches the end.

JavaScript
function canJump(a) {
  let far = 0;
  for (let i = 0; i < a.length && i <= far; i++) far = Math.max(far, i + a[i]);
  return far >= a.length - 1;
}

Time. O(n)   Space. O(1)

Why this works. You only need the farthest index reachable so far. If the current index is within farthest, you can jump forward; greedy tracking avoids recomputing reach from every cell.

Step by step.

  1. Set farthest = 0.
  2. For i from 0 to n-1, if i > farthest return false.
  3. Update farthest = max(farthest, i + nums[i]).
  4. Early true if farthest >= n - 1.
  5. After loop return farthest >= n - 1.

Trace.

nums = [2, 3, 1, 1, 4] i=0 farthest=2 i=1 farthest=4 i=2 farthest=4 i=3 farthest=4 >= last index output: true

Watch. Returning true at i == n-1 without checking whether that index was reachable (i <= farthest) accepts impossible games.

Complexity. Time O(n). Extra space O(1).

7. Coin change II (count ways)

Number of combinations (order does not matter) that make amount.

Idea. Outer loop coins, inner amount upward, so each coin is reused but combinations are not permuted.

JavaScript
function change(amount, coins) {
  const dp = Array(amount + 1).fill(0);
  dp[0] = 1;
  for (const c of coins)
    for (let x = c; x <= amount; x++) dp[x] += dp[x - c];
  return dp[amount];
}

Time. O(amount × coins)   Space. O(amount)

Why this works. Counting combinations not permutations means coin order should not double-count. Processing coins in an outer loop and amounts ascending lets each coin contribute once per combination layer.

Step by step.

  1. dp[0] = 1 way to make zero.
  2. For each coin c in coins.
  3. For amount from c to target upward.
  4. dp[amount] += dp[amount - c].
  5. Return dp[target].

Trace.

amount = 5, coins = [1, 2, 5] after 1s: dp[5]=1 after 2s: dp[5]=2 after 5: dp[5]=4 output: 4

Watch. Swapping loops (amount outer, coin inner) counts permutations like [1,2] and [2,1] separately.

Complexity. Time O(amount × coins). Extra space O(amount).

8. Unique paths with obstacles

Grid of 0 (open) and 1 (wall). Paths from top-left to bottom-right, right/down only.

Idea. Same as unique paths, but a wall stays 0 and does not receive flow. First row/col stop after the first wall.

JavaScript
function uniquePathsWithObstacles(g) {
  const m = g.length, n = g[0].length;
  if (g[0][0] === 1) return 0;
  const dp = Array.from({length:m}, () => Array(n).fill(0));
  dp[0][0] = 1;
  for (let i = 0; i < m; i++)
    for (let j = 0; j < n; j++) {
      if (g[i][j] === 1) { dp[i][j] = 0; continue; }
      if (i) dp[i][j] += dp[i - 1][j];
      if (j) dp[i][j] += dp[i][j - 1];
    }
  return dp[m - 1][n - 1];
}

Time. O(mn)   Space. O(mn)

Why this works. Same grid DP as unique paths, but walls block flow. A wall cell stays at zero paths and stops propagation along its row and column beyond it.

Step by step.

  1. If start or end is wall, return 0.
  2. Initialize first row until first wall, then zeros.
  3. Initialize first column until first wall, then zeros.
  4. For each open cell: dp[i][j] = dp[i-1][j] + dp[i][j-1].
  5. Wall cells remain 0.

Trace.

grid = [[0,0,0],[0,1,0],[0,0,0]] wall at (1,1) blocks through middle paths: down-right-around = 2 output: 2

Watch. Treating wall as 1 or adding paths through walls inflates counts. First row/col must zero out after the first obstacle.

Complexity. Time O(mn). Extra space O(mn).

Trie: a tree of prefixes

JavaScript
class TrieNode {
  constructor() { this.next = new Map(); this.end = false; }
}
class Trie {
  constructor() { this.root = new TrieNode(); }
  insert(word) {
    let n = this.root;
    for (const ch of word) {
      if (!n.next.has(ch)) n.next.set(ch, new TrieNode());
      n = n.next.get(ch);
    }
    n.end = true;
  }
  startsWith(pref) {
    let n = this.root;
    for (const ch of pref) {
      if (!n.next.has(ch)) return false;
      n = n.next.get(ch);
    }
    return true;
  }
  search(word) {
    let n = this.root;
    for (const ch of word) {
      if (!n.next.has(ch)) return false;
      n = n.next.get(ch);
    }
    return n.end;
  }
}

Better than a Set when you need prefix queries (autocomplete). Space can be large; that’s the trade-off.

Union-find: growing components

JavaScript
class UnionFind {
  constructor(n) { this.p = [...Array(n).keys()]; this.r = Array(n).fill(0); }
  find(x) {
    if (this.p[x] !== x) this.p[x] = this.find(this.p[x]);
    return this.p[x];
  }
  union(a, b) {
    a = this.find(a); b = this.find(b);
    if (a === b) return false;
    if (this.r[a] < this.r[b]) [a, b] = [b, a];
    this.p[b] = a;
    if (this.r[a] === this.r[b]) this.r[a]++;
    return true;
  }
}

Almost O(1) per op with path compression + rank. Use: connected components, Kruskal, “accounts merge,” redundant connection.

1. Replace words

dictionary of roots. For each word in the sentence, replace with the shortest root that is a prefix.

Idea. Insert roots. For each word, walk until a node with end, or fail and keep the word.

JavaScript
function replaceWords(dictionary, sentence) {
  const root = { next: new Map(), end: false };
  for (const w of dictionary) {
    let n = root;
    for (const ch of w) {
      if (!n.next.has(ch)) n.next.set(ch, { next: new Map(), end: false });
      n = n.next.get(ch);
    }
    n.end = true;
  }
  const rootOf = (w) => {
    let n = root, pref = "";
    for (const ch of w) {
      if (!n.next.has(ch)) return w;
      n = n.next.get(ch); pref += ch;
      if (n.end) return pref;
    }
    return w;
  };
  return sentence.split(" ").map(rootOf).join(" ");
}

Time. O(total chars)   Space. O(dictionary)

Why this works. Roots are prefixes, so a trie lets you stop at the shortest marked root while scanning each word character by character instead of comparing every dictionary word.

Step by step.

  1. Insert each dictionary root into a trie with end markers.
  2. Split sentence into words.
  3. Walk trie chars for each word until mismatch or end marker.
  4. Replace with path prefix if a root was found; else keep word.
  5. Join words back into the sentence string.

Trace.

dict = ["cat","bat","rat"], sentence = "the cattle was rattled" cattle: 'cat' is shortest root -> cat rattled: 'rat' -> rat output: "the cat was rat"

Watch. Storing full words at nodes without stopping at the first end marker can replace with a longer non-root prefix.

Complexity. Time O(total chars). Extra space O(dictionary).

2. Accounts merge

accounts[i] = [name, email, …]. Merge accounts that share any email. Return [name, emails sorted].

Idea. Map email→id. Union ids that share an email. Then group emails by find(id).

JavaScript
function accountsMerge(accounts) {
  const p = [...Array(accounts.length).keys()];
  const find = (x) => (p[x] === x ? x : (p[x] = find(p[x])));
  const emailTo = new Map();
  accounts.forEach((a, i) => {
    for (let k = 1; k < a.length; k++) {
      if (emailTo.has(a[k])) p[find(i)] = find(emailTo.get(a[k]));
      else emailTo.set(a[k], i);
    }
  });
  const groups = new Map();
  for (const [email, i] of emailTo) {
    const r = find(i);
    if (!groups.has(r)) groups.set(r, []);
    groups.get(r).push(email);
  }
  return [...groups.entries()].map(([r, emails]) => [accounts[r][0], ...emails.sort()]);
}

Time. O(n α(n) + sort)   Space. O(n)

Why this works. Shared emails must land in one connected component. Union-find merges accounts by email identity without building explicit graphs for every pair.

Step by step.

  1. Map each email to a unique id; union all emails in the same account row.
  2. For each id, find root with path compression.
  3. Group emails by root id.
  4. Attach the account name from any row containing that email.
  5. Sort each email list and format output.

Trace.

accounts = [["John","j@x","d@x"],["John","d@x","d@y"]] d@x links both rows -> one component {j@x,d@x,d@y} output: [["John","d@x","d@y","j@x"]]

Watch. Union-find without path compression and rank can degrade on long chains; also key emails by root, not by original row index.

Complexity. Time O(n α(n) + sort). Extra space O(n).

3. Redundant connection

Undirected graph with n edges on n nodes (1-based) — exactly one extra edge. Return that edge.

Idea. Union edges. The first edge whose ends are already in the same component is the extra.

JavaScript
function findRedundantConnection(edges) {
  const n = edges.length, p = [...Array(n + 1).keys()];
  const find = (x) => (p[x] === x ? x : (p[x] = find(p[x])));
  for (const [a, b] of edges) {
    const ra = find(a), rb = find(b);
    if (ra === rb) return [a, b];
    p[rb] = ra;
  }
}

Time. O(n α(n))   Space. O(n)

Why this works. A tree on n nodes has exactly n-1 edges; the extra edge closes a cycle. Union-find rejects the first edge whose endpoints were already connected.

Step by step.

  1. Initialize parent[i] = i for 1..n.
  2. Process edges in given order.
  3. Find roots of u and v with compression.
  4. If roots equal, return this edge as redundant.
  5. Else union the roots and continue.

Trace.

edges = [[1,2],[1,3],[2,3]] union 1-2, union 1-3 2-3 already same component output: [2, 3]

Watch. Union by size without find compression still works but is slower; returning the last edge in the cycle instead of the first given redundant edge fails the problem.

Complexity. Time O(n α(n)). Extra space O(n).

4. Range sum query (immutable)

Class(nums) then sumRange(l, r) inclusive, many queries, O(1) each.

Idea. pref[0]=0, pref[i+1] = pref[i]+nums[i]. Query pref[r+1]-pref[l].

JavaScript
class NumArray {
  constructor(nums) {
    this.pref = [0];
    for (const x of nums) this.pref.push(this.pref[this.pref.length - 1] + x);
  }
  sumRange(l, r) { return this.pref[r + 1] - this.pref[l]; }
}

Time. O(n) build, O(1) query   Space. O(n)

Why this works. Prefix sums turn any range sum into two lookups. Building pref once makes each sumRange O(1) after O(n) preprocessing instead of re-summing l..r per query.

Step by step.

  1. Build pref with pref[0] = 0.
  2. For i from 0 to n-1: pref[i+1] = pref[i] + nums[i].
  3. sumRange(l, r) returns pref[r+1] - pref[l].
  4. Store pref on the object for reuse.
  5. No mutation of nums assumed.

nums = [-2, 0, 3, -5, 2, -1] pref = [0,-2,-2,1,-4,-2,-3] sumRange(0,2) = pref[3]-pref[0] = 1-0 = 1 output: 1

5. Next greater circular

Next greater element to the right, wrapping around. -1 if none.

Idea. Monotonic decreasing stack of indexes. Iterate i from 0 to 2n-1, look at a[i%n]. Only push when i < n.

JavaScript
function nextGreaterElements(a) {
  const n = a.length, ans = Array(n).fill(-1), st = [];
  for (let i = 0; i < 2 * n; i++) {
    const x = a[i % n];
    while (st.length && a[st[st.length - 1]] < x) ans[st.pop()] = x;
    if (i < n) st.push(i);
  }
  return ans;
}

Time. O(n)   Space. O(n)

Why this works. A decreasing stack keeps candidates waiting for a bigger future value. Walking 2n indices simulates the circular wrap so elements at the end can see larger values from the start.

Step by step.

  1. Initialize result with -1 and empty stack of indices.
  2. Loop i from 0 to 2n - 1.
  3. While stack nonempty and nums[i % n] > nums[stack.top], set result[pop] = nums[i % n].
  4. If i < n, push i onto stack.
  5. Return result.

Trace.

nums = [1, 2, 1] i=0 push 0; i=1 pop 0 result[0]=2 push 1 wrap: i=3 value 1 no pop; i=4 value 2 pop 1 result[1]=2 output: [2, -1, 2]

Complexity. Time O(n). Extra space O(n).

6. Suggested products

products and a searchWord. After each typed character, up to 3 products that have that prefix, lexicographically.

Idea. Sort products. For each prefix, lower-bound and take the next 3 that still match. Trie also works.

JavaScript
function suggestedProducts(products, searchWord) {
  products.sort();
  const out = [];
  let pref = "";
  for (const ch of searchWord) {
    pref += ch;
    let lo = 0, hi = products.length;
    while (lo < hi) {
      const m = (lo + hi) >> 1;
      if (products[m] < pref) lo = m + 1; else hi = m;
    }
    const row = [];
    for (let i = lo; i < products.length && row.length < 3; i++) {
      if (!products[i].startsWith(pref)) break;
      row.push(products[i]);
    }
    out.push(row);
  }
  return out;
}

Time. O(n log n + L · n)   Space. O(n)

Why this works. Lexicographic top-3 prefixes are the first three sorted products with that prefix. Sort once, then lower-bound each search prefix and scan forward while matches hold.

Step by step.

  1. Sort products lexicographically.
  2. For each prefix length of searchWord.
  3. Binary search lower bound for prefix in products.
  4. Collect up to 3 products starting there that still start with prefix.
  5. Append list to answer; stop early if prefix not found.

Trace.

products = ["mobile","mouse","moneypot","monitor"], searchWord = "mouse" m -> mobile, moneypot, monitor mo -> mobile, monitor, mouse mou -> mouse mous -> mouse mouse -> mouse

Watch. Taking any three matches without lex order, or not stopping the forward scan when prefix breaks, returns wrong suggestions.

Complexity. Time O(n log n + L · n). Extra space O(n).

8. Car fleet

Cars go to target. Position and speed. A faster car stuck behind a slower one becomes one fleet. How many fleets arrive?

Idea. Sort by position descending (closest to target first). Track the slowest arrival time so far. A car with a larger time is a new fleet.

JavaScript
function carFleet(target, position, speed) {
  const cars = position.map((p, i) => [p, (target - p) / speed[i]]).sort((a, b) => b[0] - a[0]);
  let fleets = 0, slow = 0;
  for (const [, t] of cars) {
    if (t > slow) { fleets++; slow = t; }
  }
  return fleets;
}

Time. O(n log n)   Space. O(n)

Why this works. Cars cannot pass, so a faster car behind a slower one forms a fleet with the slower arrival time. Processing from target-nearest downward merges stacks by comparing arrival times.

Step by step.

  1. Pair position with speed; sort by position descending.
  2. Track fleet arrival time as max time seen so far.
  3. For each car compute time = (target - pos) / speed.
  4. If time > fleet time, push new fleet count and update fleet time.
  5. Return fleet count.

LRU cache

Problem. Keep the K most recently used keys. get/put in O(1).

Structure / algorithm. Map (insertion order in JS is specified) or Map + doubly linked list. JS Map: delete + set moves a key to the end.

JavaScript
class LRUCache {
  constructor(capacity) { this.cap = capacity; this.map = new Map(); }
  get(key) {
    if (!this.map.has(key)) return -1;
    const v = this.map.get(key);
    this.map.delete(key);
    this.map.set(key, v);
    return v;
  }
  put(key, value) {
    if (this.map.has(key)) this.map.delete(key);
    this.map.set(key, value);
    if (this.map.size > this.cap) {
      const oldest = this.map.keys().next().value;
      this.map.delete(oldest);
    }
  }
}

Where this shows up at work. Image/cache of API responses, tab keep-alive (cap 3–5), parsed module cache.

Trap. Using an array + indexOf is O(n). Forgetting to refresh on get.

Autocomplete

Problem. Type a prefix, return up to 10 words.

Structure / algorithm. Trie + DFS/BFS collect, or a sorted array + binary search on prefix (simpler, O(n) collect).

JavaScript
function suggest(trie, prefix, limit = 10) {
  let n = trie.root;
  for (const ch of prefix) {
    if (!n.next.has(ch)) return [];
    n = n.next.get(ch);
  }
  const out = [];
  function dfs(node, path) {
    if (out.length >= limit) return;
    if (node.end) out.push(path);
    for (const [ch, nxt] of node.next) dfs(nxt, path + ch);
  }
  dfs(n, prefix);
  return out;
}

Where this shows up at work. Command palette, mention lists, Jira key search. Production still needs server authz so private titles never leak.

Rate limiter (sliding window)

Problem. Allow at most N requests per user per W milliseconds.

Structure / algorithm. Queue of timestamps per key; drop those older than now-W.

function allow(buckets, key, now, n, windowMs) {
  const q = buckets.get(key) || [];
  const cut = now - windowMs;
  while (q.length && q[0] <= cut) q.shift();
  if (q.length >= n) { buckets.set(key, q); return false; }
  q.push(now);
  buckets.set(key, q);

1. Two sum

Return indices of two numbers that add to target. Same index twice is illegal.

Idea. One pass Map: value → index. Need = target − nums[i].

JavaScript
function twoSum(nums, target) {
  const seen = new Map();
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    if (seen.has(need)) return [seen.get(need), i];
    seen.set(nums[i], i);
  }
  return [];
}

Time. O(n)   Space. O(n)

Why this works. Checking every pair takes quadratic time because you re-scan the array for each element. A hash map remembers what you have already seen, so each lookup is constant time. One left-to-right pass is enough because the partner for nums[i] must appear earlier or you store i for later.

Step by step.

  1. Create an empty map from value to index.
  2. Walk i from 0 to n-1.
  3. Compute need = target - nums[i].
  4. If need is already in the map, return [map[need], i].
  5. Otherwise store nums[i] -> i and continue.
  6. Return empty if no pair exists.

Trace.

nums = [2, 7, 11, 15], target = 9 i=0: need=7, map={}, store 2->0 i=1: need=2, map has 2 at 0 -> return [0, 1]

Complexity. Time O(n). Extra space O(n).

7. Product of array except self

9. 3Sum

Unique triplets that sum to 0.

Idea. Sort. Fix i. Two pointers. Skip duplicates.

function threeSum(nums) {
  nums.sort((a, b) => a - b);
  const out = [];
  for (let i = 0; i < nums.length; i++) {
    if (i && nums[i] === nums[i - 1]) continue;
    let lo = i + 1, hi = nums.length - 1;
    while (lo < hi) {
      const s = nums[i] + nums[lo] + nums[hi];
      if (s === 0) {
        out.push([nums[i], nums[lo], nums[hi]]);
        while (lo < hi && nums[lo] === nums[lo + 1]) lo++;
        while (lo < hi && nums[hi] === nums[hi - 1]) hi--;
        lo++; hi--;
      } else if (s < 0) lo++;
      else hi--;
    }
  }
  return out;
}

Time. O(n²)   Space. O(1) extra

Why this works. A triple nested loop finds triplets but emits many duplicates. Sorting lets you fix one value and use two pointers on the remainder in linear time. Skipping equal neighbors after a match removes duplicate triplets without a separate set.

  1. Sort nums.
  2. For i from 0 to n-3:
  3. Skip duplicate nums[i].
  4. Set lo = i+1, hi = n-1.
  5. While lo < hi: if sum==0 record and skip dupes; elif sum<0 lo++; else hi--.
  6. Return collected triplets.

nums = [-1, 0, 1, 2, -1, -4] -> sorted [-4,-1,-1,0,1,2] i=1 (-1): lo=2 hi=5 -> (-1,0,1) and (-1,-1,2)

38. Merge intervals

42. LRU cache

get/put O(1), evict least recently used.

Idea. Map insertion order (or DLL + Map).

JavaScript
class LRUCache {
  constructor(cap) { this.cap = cap; this.m = new Map(); }
  get(k) {
    if (!this.m.has(k)) return -1;
    const v = this.m.get(k); this.m.delete(k); this.m.set(k, v); return v;
  }
  put(k, v) {
    if (this.m.has(k)) this.m.delete(k);
    this.m.set(k, v);
    if (this.m.size > this.cap) this.m.delete(this.m.keys().next().value);
  }
}

Time. O(1)   Space. O(cap)

Why this works. A map alone does not track recency for eviction. Pair a hash map (key to node) with a doubly linked list in MRU-to-LRU order. get and put splice the node to the front in O(1).

Step by step.

  1. Map key -> list node; dummy head/tail DLL.
  2. get(key): if missing return -1; move node to front; return val.
  3. put(key,val): update or create node at front.
  4. If size > capacity, remove LRU tail and erase from map.

Trace.

cap=2: put(1,1) put(2,2) get(1)->1 put(3,3) evicts key 2 get(2) -> -1

Watch. Updating an existing key must refresh its position, not only its value, or LRU order is wrong.

44. Word search

Does word exist in a grid (adjacent cells, no reuse)?

Idea. DFS + mark visited.

JavaScript
function exist(board, word) {
  const R = board.length, C = board[0].length;
  function dfs(r, c, i) {
    if (i === word.length) return true;
    if (r<0||c<0||r>=R||c>=C||board[r][c]!==word[i]) return false;
    const t = board[r][c]; board[r][c] = '#';
    const ok = dfs(r+1,c,i+1)||dfs(r-1,c,i+1)||dfs(r,c+1,i+1)||dfs(r,c-1,i+1);
    board[r][c] = t;
    return ok;
  }
  for (let r=0;r<R;r++) for (let c=0;c<C;c++) if (dfs(r,c,0)) return true;
  return false;
}

Time. O(RC · 4^L)   Space. O(L)

Why this works. Brute force from every cell repeats path work. DFS from each match of the first letter explores only viable paths with backtracking. Mark cells visited during a path, then restore them when unwinding.

Step by step.

  1. For each cell matching word[0]:
  2. Run dfs(r,c, index).
  3. If out of bounds or mismatch, return False.
  4. If index == len(word)-1, return True.
  5. Mark visited, try 4 neighbors, unmark.
  6. Return False if all fail.

Trace.

board ABCE, word ACE start A(0,0) -> C(1,0) -> E(0,2) -> True

Watch. Restore the cell after backtracking; permanent marks block other paths through that cell.

Complexity. Time O(RC · 4^L). Extra space O(L).

function trap(h) {

      L = Math.max(L, h[lo]);

46. Median of two sorted arrays

function findMedianSortedArrays(a, b) {
  if (a.length > b.length) return findMedianSortedArrays(b, a);
  const m = a.length, n = b.length;
  let lo = 0, hi = m;
  while (lo <= hi) {
    const i = (lo + hi) >> 1;
    const j = ((m + n + 1) >> 1) - i;
    const aL = i ? a[i-1] : -Infinity, aR = i < m ? a[i] : Infinity;
    const bL = j ? b[j-1] : -Infinity, bR = j < n ? b[j] : Infinity;
    if (aL <= bR && bL <= aR) {
      if ((m+n) % 2) return Math.max(aL, bL);
      return (Math.max(aL, bL) + Math.min(aR, bR)) / 2;
    }
    if (aL > bR) hi = i - 1;
    else lo = i + 1;
  }
}

Time. O(log min(m,n))   Space. O(1)

Why this works. Merging both arrays defeats the logarithmic requirement. The median splits combined sorted order at a partition; binary search that cut on the shorter array. Ensure max(left halves) <= min(right halves) to validate a partition.

Step by step.

  1. Ensure A is the shorter array.
  2. Binary search cut i in A (0..m).
  3. j = (m+n+1)//2 - i in B.
  4. Compare A[i-1], B[j-1] vs A[i], B[j] for cross-boundary order.
  5. Adjust i until valid; compute median from boundary values.

A=[1,3], B=[2] partition i=1 j=1 left max 3? check B[j-1]=2 ok median = 2

Watch. Handle empty halves with +/- infinity sentinels; off-by-one on i and j breaks boundary comparisons.

function ladderLength(begin, end, wordList) {
  const set = new Set(wordList);
  if (!set.has(end)) return 0;
  const q = [[begin, 1]];
  const seen = new Set([begin]);
  while (q.length) {
    const [w, d] = q.shift();

    for (let i = 0; i < w.length; i++) {

    }
  }
  return 0;
}

            Language

            Glossary

            Adjacency list

            Graph as node → list of neighbors. Default for sparse graphs.

            Amortized O(1)

            Average cost per op if expensive resizes are rare (e.g. push).

            BFS

            Queue. Level by level. Shortest hops on unweighted graphs.

            Binary search

            Halve a sorted range. Watch lo/hi and mid overflow.

            BST

            Left < node < right (consistent with equals policy). Height is not automatically log n.

            Backtracking

            Choose, recurse, unchoose. Copy the path when you store a result.

            Big O

            Growth of worst-case work (or space) as n grows.

            Cycle (Floyd)

            Two pointers at different speeds meet if a list loops.

            DFS

            Stack or recursion. Paths, components, topo via postorder.

            Dummy node

            Fake list head so insert/merge never special-cases the first real node.

            Heap (binary)

            Array-backed complete tree. Children at 2i+1 and 2i+2.

            Indegree

            Count of incoming edges. Kahn starts at indegree 0.

            Kadane

            Best subarray ending here = max(x, prevEnding + x).

            Kahn

            Topo sort by peeling indegree-0 nodes. leftover nodes ⇒ cycle.

            LRU

            Evict least recently used. Map insertion order, or Map + doubly linked list.

            Memoization

            Top-down DP: cache answers to a named state.

            Monotonic stack

            Indexes whose values stay increasing or decreasing. Next-greater family.

            Prefix sum

            pref[i] = sum of first i. Range = pref[r] − pref[l].

            Sliding window

            Two indexes that only move forward. Fixed k or shrink while invalid.

            Tabulation

            Bottom-up DP. Loops from base cases, often rollable.

            Topological order

            A before B if A must happen first. DAG only.

            Trie

            Prefix tree. Each edge is a character. startsWith is O(length).

            Two pointers

            Lo/hi or slow/fast. Needs an invariant (sorted, or partition).

            Union-find

            Disjoint sets. find(root) + union. Path compression + rank ≈ O(1).

            Visited

            Mark when first seen (usually enqueue) so BFS/DFS do not explode.
