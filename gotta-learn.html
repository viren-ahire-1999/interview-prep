30 days · OpenShift Observe UI

Gotta learn before we start

You already know React and TypeScript. The extra edge is not another framework. It is speaking Observe the way this team ships it: OpenShift console dynamic plugins, PatternFly 6, and turning metrics, logs, and traces into one troubleshooting path — then landing that in upstream GitHub.

What “ready” means here

Console plugins PatternFly 6 PromQL / LogQL / TraceQL Perses Korrel8r Accessibility

This is a 30-day onboarding guide for an observability UI lead role on OpenShift. You sit between backend signal teams, product, and UX. You do not need to write operators. You do need to read YAML, query three backends, and review plugin PRs like a senior.

You will be able to

  • Explain a ConsolePlugin and a UIPlugin CR
  • Build UI that looks like PatternFly 6, not a SaaS dashboard
  • Say why plugins must not import PatternFly CSS
  • Pick the right signal: metric vs log vs trace
  • Write a useful PromQL and a useful LogQL
  • Follow one request through OpenTelemetry into Tempo
  • Sketch Korrel8r: alert → related logs, metrics, pods
  • Talk empty / error / partial-query states with backend

Why this file exists

The job

You are the UI catalyst, not a dashboard contractor

The job is to shape how people experience observability across OpenShift and multi-cluster management — not to paint charts in isolation.

Backend teams own Prometheus, Loki, Tempo, Alertmanager. You own the single pane: time range, empty states, RBAC-aware lists, and jumps between signals. Product and UX sit in the same design conversation.

PM / UX ──► you (plugin + PF + a11y) metrics team logging team tracing team └── UIPlugin / ConsolePlugin ──► Observe menu

Lead means you propose a plugin boundary, a proxy, a feature flag, and a PatternFly pattern — not a new SPA. Upstream means the feature lands on GitHub first, then in the operator that installs it on a cluster.

React fluency is assumed. The people who move fastest can explain ConsolePlugin, UIPlugin, and why a PromQL range query, a Loki stream, and a Tempo trace share one troubleshooting journey.

How code reaches the cluster

Console plugins

Dynamic plugins: Webpack federation, not a new app

The console loads remote JavaScript at runtime (Webpack 5 module federation). You register a ConsolePlugin custom resource. A cluster admin enables it on the console Operator: spec.plugins.

plugin webpack build → HTTP server on cluster ConsolePlugin CR → console Operator spec.plugins browser loads chunks → Observe nav + pages

If the UI must call an in-cluster service, declare spec.proxy. The console backend exposes /api/proxy/plugin/…. Default is HTTPS with the service CA. This is why several plugins ship a small Go server: serve assets + proxy Loki/Tempo/Korrel8r.

YAML
apiVersion: console.openshift.io/v1
kind: ConsolePlugin
metadata:
  name: example-observe
spec:
  displayName: Example Observe
  backend:
    service:
      name: example-plugin
      namespace: example
      port: 9443
  proxy:
    - objectRef:
        name: loki
        namespace: openshift-logging
        kind: Service
      authorization: UserToken

Start from openshift/console-plugin-template. Metadata lives in package.json → consolePlugin. Routes and nav live in console-extensions.json. Use Yarn and Webpack as the READMEs do — Vite is not the console contract.

Do not import PatternFly CSS in the plugin. Prefix any custom class with the plugin name. Avoid element selectors that leak outside your tree.

COO installs your UI with a UIPlugin CR

For Observe extras, COO watches a UIPlugin and deploys the matching plugin + backends (for example Korrel8r next to the troubleshooting panel, or Perses when monitoring.perses is enabled).

YAML
apiVersion: observability.openshift.io/v1alpha1
kind: UIPlugin
metadata:
  name: monitoring
spec:
  type: Monitoring
  monitoring:
    perses:
      enabled: true

If Console is GitOps-managed, the plugin name must be in the git Console spec or a sync will disable it. That is an operations bug that looks like a frontend regression.

Design system

PatternFly 6

PatternFly 6 is the house look. Tailwind is a defect.

OpenShift 4.19 unified admin/developer perspectives and moved the console to PatternFly 6. Console 4.22 is PF 6. New plugins should target PF 6. The console loads PF base styles. If you import @patternfly/patternfly or PF CSS files, you fight theming (including dark/light) and future upgrades.

  • Use PF React components and CSS variables from the SDK / PF packages as the plugin docs allow.
  • SDK wrappers exist (for example list page headers). Prefer those when the console already has a pattern.
  • No Bootstrap, no Tailwind, no random chart CSS that restyles body.
  • Accessibility is in the job description. Keyboard, focus order, contrast, name/role/value, charts that are not color-only. Use axe plus a keyboard pass. PF accessibility docs are the standard.
  • i18n: react-i18next. Hard-coded English in a header is a review block on this team.
A senior review comment you should be ready to leave: ‘This is a custom div that PF already has as Toolbar / Pagination / EmptyState. Use the component so we inherit a11y and theme.’

Domain

Three signals

Three signals, one journey

A metric is an aggregate over time (CPU, error rate). A log is an event with a payload. A trace is one request across services (spans). Excellent Observe UI does not dump all three on one page. It starts in the right place and jumps with time range and filters intact.

CrashLoop → logs first, then metrics (restarts), then events High p99 → metrics + trace (who is slow) Auth 401s → logs + trace attributes (user, route) ‘Everything is on fire’ → incidents / Alertmanager, not raw 4000 alerts

Cardinality: high-cardinality labels in Prometheus will melt the backend and the chart. The UI should not invite unbounded label selectors without a warning.

Languages

Query languages

PromQL, LogQL, TraceQL — minimum fluency

You will sit in design reviews where a backend engineer says “just use this query.” You need to know if the UI can show empty, error, timeout, and partial results.

  • PromQL: instant vs range, rate() vs irate(), histogram_quantile, by/without, recording vs alerting rules. Write ten queries on a real Prometheus.
  • LogQL: stream selectors, line filters, JSON unpack, then metric queries over logs. The logging plugin has a schema switch: legacy viaq vs OTel logs.
  • TraceQL: find traces by service, duration, status, attributes. Waterfall, span links, exemplars from metrics into traces. OTel semantic conventions (service.name, k8s, http).
text
# PromQL — request rate
sum(rate(http_requests_total[5m])) by (code)

# LogQL — errors in a namespace
{kubernetes_namespace_name="shop"} |= "error"

# TraceQL — slow checkouts
{ resource.service.name = "checkout" && duration > 2s }

Jaeger still appears in older talks. Current tracing UI on OpenShift is Tempo plus the OpenTelemetry collector. Learn Tempo; do not become a Jaeger maintainer.

Performance: abort in-flight fetches when the time picker moves. Cap series. Virtualize huge log/trace tables. A pretty chart that freezes the console is a P1.

Visualization future

Perses

Perses is dashboards as cluster resources

Perses is an open-source, cloud-native dashboard tool. On OpenShift it is wired through COO: Observe → Dashboards (Perses). Dashboards and datasources are namespace-scoped CRDs, which matches Kubernetes RBAC and GitOps (dashboard as YAML).

  • Graphical editor in the console (create, rename, duplicate).
  • Grafana import for the migration story — you should know it exists, not become a Grafana plugin author.
  • Datasources: Prometheus / Thanos, Loki, Tempo (as documented for the build you target).
  • PatternFly theming work already exists in monitoring-plugin so Perses does not look like a foreign app.
If you can run one thing extra in week 3: clone perses-dev/perses, create a dashboard as YAML, import one Grafana JSON. That conversation comes up constantly.

The JD’s ‘unified UI workflows’

Correlation

Correlation is the unified workflow

Korrel8r is an open-source correlation engine (rules that connect alerts, metrics, logs, pods, netflows). The troubleshooting panel turns results into an interactive graph. Click a node → the matching Observe or workload page with the right query.

Alert firing → Korrel8r query → nodes: metrics, logs, pod, netflow → click → console URL with filters If Logging plugin is missing, log nodes will not render usefully.

The panel plugin maps Korrel8r domains to OpenShift URLs. Those mappings must stay accurate — the repo calls out extensive unit tests. Breaking a URL map is a silent product bug: the graph looks fine, the click goes to the wrong page.

Clone korrel8r/korrel8r and openshift/troubleshooting-panel-console-plugin. Read AGENTS.md in the panel repo.

Ship a Hello Observe plugin

Problem. You need a page under Observe that is not a new SPA.

Approach. Clone console-plugin-template. Keep Webpack + Yarn. Register consolePlugin in package.json, a console-extensions.json nav item, a ConsolePlugin CR. Enable spec.plugins. Do not import PatternFly CSS.

JSON
{
  "consolePlugin": {
    "exposedModules": { "./ObservePage": "./src/components/ObservePage" }
  }
}

Where this shows up. Every Observe UI that is not baked into the console binary.

Trap. Starting a Vite app and iframe-ing it into the console.

Logs page without CORS hacks

Problem. The browser cannot talk to Loki directly. Copy-paste fetch to an internal URL fails CORS and RBAC.

Approach. Declare spec.proxy to the Loki service. Call /api/proxy/plugin//…. Go (or the template server) terminates TLS with the service CA. Send the user token if the CR says so.

YAML
spec:
  proxy:
    - objectRef:
        name: loki
        namespace: openshift-logging
        kind: Service
      authorization: UserToken

Where this shows up. logging-view-plugin, tracing plugin, Korrel8r panel.

Trap. Hard-coding a cluster IP in frontend code.

Filterable list that looks like the console

Problem. PM wants a ‘nice dashboard table’ of firing alerts.

Approach. Toolbar + filter + pagination + EmptyState from PatternFly 6. Keyboard through the toolbar. Prefix any extra class with the plugin name.

TSX
<Toolbar>
  <ToolbarContent>
    <SearchInput value={q} onChange={(_, v) => setQ(v)} />
  </ToolbarContent>
</Toolbar>
{rows.length ? <Table rows={rows} /> : <EmptyState titleText="No alerts" />}

Where this shows up. Alerting, log lines, trace search hits.

Trap. Tailwind table + custom pagination that skips PF a11y.

CrashLoop: pick the first click

Problem. A deployment is CrashLooping. The user is already in the console.

Approach. Logs first (why did the process die). Then metrics (restart count). Then events / Korrel8r for related objects. Do not open a 40-panel Grafana board as v1.

text
CrashLoop
  1. Observe → Logs  (last lines, previous container)
  2. Metrics         (restarts, CPU OOM?)
  3. Troubleshooting (related pods, alerts)

Where this shows up. Workload debugging from Observe.

Trap. Starting with a custom dashboard because it looks senior.

Error-rate chart that will not melt Prometheus

Problem. Show request error ratio for a service. Someone wants a label for every user id.

Approach. rate() on a counter, then divide 5xx by total. Aggregate by code or route — never by user. Cap series in the UI. Abort the fetch when the time picker moves.

PromQL
sum(rate(http_requests_total{code=~"5.."}[5m]))
/
sum(rate(http_requests_total[5m]))

Where this shows up. Metrics pages, Perses panels, ACM aggregated views.

Trap. histogram_quantile on a high-cardinality label without a recording rule.

Find checkout errors without grepping a node

Problem. Checkout is failing for one namespace. Logs are in Loki.

Approach. Stream selector first (namespace, container), then a line filter, then JSON unpack if the schema is structured. Know viaq vs OTel field names before you invent a filter.

LogQL
{kubernetes_namespace_name="shop", app="checkout"}
  |= "error"
  | json

Where this shows up. logging-view-plugin query bar.

Trap. A regex across all tenants because ‘it worked in grep’.

Dashboard as a namespaced CR

Problem. Platform team wants the same SLO board in every shop namespace, reviewable in git.

Approach. Perses dashboard + datasource CRs, not a Grafana folder nobody owns. Import Grafana JSON once as a migration, then treat YAML as source of truth.

YAML
apiVersion: perses.dev/v1alpha1
kind: PersesDashboard
metadata:
  name: checkout-slo
  namespace: shop
spec:
  display:
    name: Checkout SLO

Where this shows up. Observe → Dashboards (Perses).

Trap. Editing production Grafana by hand forever.

Alert click that must not 404

Problem. The graph shows a log node. Click should open Observe → Logs with the right query.

Approach. Keep the domain → console URL map in lockstep with plugin routes. Add a unit test for the href. If Logging is not installed, the node should say so — not fail silently.

text
alert node
  → korrel8r neighbours
  → console URL (plugin route + query)
  → tests: snapshot the href

Where this shows up. troubleshooting-panel-console-plugin.

Trap. Pretty graph, wrong href. Looks like a backend bug.

Plugin vanished after a sync

Problem. You enabled a plugin in the UI. Next morning it is gone. GitOps owns the Console CR.

Approach. The plugin name must be in the git Console spec. A live toggle without git is a race the reconcilers will win.

YAML
apiVersion: operator.openshift.io/v1
kind: Console
spec:
  plugins:
    - monitoring-plugin
    - logging-view-plugin

Where this shows up. Any cluster with Argo/ACM policy on console.

Trap. Debugging Webpack for a day when git overwrote spec.plugins.

A chart a keyboard user can use

Problem. Error vs OK is red vs green. Color-blind and screen-reader users get nothing.

Approach. Pattern + label + not color-only. Summary in text. Live region for ‘query failed’. Focus order through the time picker, then the chart, then the table.

text
OK:  pattern + "2xx" label
ERR: pattern + "5xx" label
SR:  "Query failed: timeout" in a live region

Where this shows up. Every Observe chart.

Trap. Custom canvas with no name/role/value.

24 questions

Q&A

Answer standing up. Mark complete only if you can teach the short answer. Practice items — not official company lists.

pluginconsoleQ1

1. What is an OpenShift console dynamic plugin?

Short answer. A Webpack 5 federated bundle the console loads at runtime, registered with a ConsolePlugin CR.

Deep explanation. You are not shipping a second SPA. Nav, pages, and tabs are console-extensions. Admins enable the plugin on the console Operator spec.plugins list.

Common misconception. It is an iframe of Grafana.

Follow-up. Where do proxy routes for Loki live?

pluginconsoleQ2

2. Why does a plugin declare spec.proxy?

Short answer. So the console backend can reach in-cluster services (Loki, Tempo, Korrel8r) with TLS and optional user token.

Deep explanation. The browser must not CORS-hack cluster IPs. Default is HTTPS plus the service CA. Several plugins add a small Go server to serve assets and proxy.

Common misconception. proxy is only for external CDNs.

Follow-up. What URL prefix does the console expose for plugin proxies?

pluginconsoleQ3

3. What is a UIPlugin CR for?

Short answer. Cluster Observability Operator watches it and deploys the matching Observe UI (and backends) for you.

Deep explanation. Example: type Monitoring with perses.enabled installs Perses wiring. You still need the plugin name on the Console spec if GitOps owns it.

Common misconception. UIPlugin replaces ConsolePlugin.

Follow-up. What happens if GitOps Console spec omits the plugin name?

pluginconsoleQ4

4. Why Webpack 5 and Yarn, not Vite, for these plugins?

Short answer. The console’s module federation contract is Webpack 5. The template and sibling plugins are Yarn.

Deep explanation. Vite can be a fine app bundler elsewhere. Here, mismatch means the remote entry never loads. Follow the template until you have a reason and a reviewer.

Common misconception. Any bundler is fine if the JS is valid.

Follow-up. What file lists exposed modules for federation?

pluginconsoleQ5

5. Why must plugins not import PatternFly CSS?

Short answer. The console already loads PF. A second copy fights theme (including dark/light) and future PF upgrades.

Deep explanation. Prefix custom classes with the plugin name. Avoid element selectors that leak. Use PF React components and CSS variables.

Common misconception. Importing @patternfly/patternfly makes it look more ‘official’.

Follow-up. What OpenShift version moved the console to PatternFly 6?

patternflyuiQ6

6. What does PatternFly 6 change for a plugin author?

Short answer. OCP 4.19+ console is PF 6. New plugins should target PF 6, not PF 4/5 or Tailwind.

Deep explanation. Use PF components the console already uses (Toolbar, Pagination, EmptyState). Accessibility and theme come with them.

Common misconception. PF is optional if your charts look modern.

Follow-up. Name a review comment you would leave on a custom div that is already a PF component.

patternflyuiQ7

7. What is an accessibility miss that will fail a senior review?

Short answer. Color-only charts, no keyboard path through the toolbar, unlabeled icon buttons, missing live region on query failure.

Deep explanation. WCAG is in the job. axe plus a keyboard pass. Name/role/value on custom widgets. i18n keys — hard-coded English in a header is a block.

Common misconception. a11y is a nice-to-have after GA.

Follow-up. How would you announce ‘query timed out’ to a screen reader?

signalsdomainQ8

8. When do you start with logs vs metrics vs traces?

Short answer. Logs: a specific event (crash, 401). Metrics: aggregates (error rate, p99). Traces: one request across services.

Deep explanation. CrashLoop → logs, then restart metrics. High p99 → metrics then trace. Auth failures → logs plus trace attributes.

Common misconception. Always open traces first because they are richest.

Follow-up. What do you open if ‘everything is on fire’?

signalsdomainQ9

9. Why is a high-cardinality label a UI bug as well as a backend bug?

Short answer. The chart invites unbounded series; Prometheus and the browser both melt.

Deep explanation. Do not offer user-id as a PromQL group-by. Cap series. Warn. Prefer recording rules for expensive queries.

Common misconception. The UI should run whatever query the user typed.

Follow-up. How do you abort work when the time picker moves?

querypromqlQ10

10. rate() vs irate() — when is rate() the default?

Short answer. rate() averages over the range; use it for graphs and SLOs. irate() uses the last two points — spiky, for instant troubleshooting.

Deep explanation. Counters need increase/rate, not a raw gauge plot. histogram_quantile needs a histogram. by/without must match the question.

Common misconception. irate is always more accurate.

Follow-up. Write PromQL for 5xx ratio without grouping by user.

querylogqlQ11

11. What is a LogQL stream selector vs a line filter?

Short answer. Selector picks streams (labels). Line filter then greps the payload. JSON unpack is after that.

Deep explanation. The logging plugin schema switch (viaq vs OTel) changes field names. Inventing {app=} on the wrong schema returns empty, not an error you can see.

Common misconception. LogQL is grep on every node disk.

Follow-up. Why might a filter that worked last year return nothing after OTel migration?

querytraceqlQ12

12. What is TraceQL for?

Short answer. Find traces in Tempo by service, duration, status, attributes — then open a waterfall.

Deep explanation. OTel semantic conventions (service.name, k8s, http) are the join keys with metrics and logs. Exemplars can jump metric → trace.

Common misconception. Jaeger is the current OpenShift tracing UI.

Follow-up. When is a trace the wrong first click?

20. Why are hard-coded English strings a review block?

Short answer. Console plugins are translated with react-i18next. English in a header skips that pipeline.

Deep explanation. Keys live with the plugin. You will see this on every sibling repo. Treat it as part of Done.

Common misconception. English-only is fine for an internal plugin.

Follow-up. Where do you look for existing keys before adding a new one?

signalsincidentsQ21

21. What is the incidents surface for?

Short answer. Group alert bursts into a timeline so humans are not staring at 4000 raw alerts.

Deep explanation. It is a COO cluster-health feature, not a replacement for Alertmanager. Start here when ‘everything is on fire.’

Common misconception. Incidents replace Prometheus rules.

Follow-up. When do you still open Alertmanager / metrics?

queryotelQ22

22. What OpenTelemetry pieces should a UI engineer actually know?

Short answer. Semantic conventions, collector as the pipeline, Tempo as the store, exemplars as metric→trace jumps.

Deep explanation. You do not need to write the collector config on day 1. You do need to know why service.name is the join key and why Jaeger is legacy talk.

Common misconception. OTel is a React library.

Follow-up. Name one attribute you would show on a trace search row.

persesgrafanaQ23

23. How should you talk about Grafana in this codebase?

Short answer. Import path and migration story. Do not become a Grafana plugin author as the plan.

Deep explanation. Perses is the Kubernetes-native board. Grafana JSON in is a bridge. Know that the conversation exists.

Common misconception. Grafana is the Observe dashboards page.

Follow-up. What object type would you GitOps instead of a Grafana folder?

korrel8ruxQ24

24. Why can a Korrel8r graph look ‘done’ and still be a P1?

Short answer. Clicks must land on the right Observe page with the right query. Wrong href is silent.

Deep explanation. Extensive URL-map tests exist for a reason. Missing sibling plugins (logging) need honest empty copy.

Common misconception. If the graph renders, the product works.

Follow-up. What would you test besides snapshotting SVG positions?

1. Sketch a ConsolePlugin CR

Write YAML: plugin name, backend service, one Loki proxy with UserToken. Then say how an admin enables it.

Idea. ConsolePlugin is console.openshift.io/v1. Enable via console Operator spec.plugins. Proxy is how the browser reaches Loki.

text
apiVersion: console.openshift.io/v1
kind: ConsolePlugin
metadata:
  name: example-observe
spec:
  displayName: Example Observe
  backend:
    service:
      name: example-plugin
      namespace: example
      port: 9443
  proxy:
    - objectRef:
        name: loki
        namespace: openshift-logging
        kind: Service
      authorization: UserToken
# enable: Console spec.plugins += example-observe

Why it matters. Wrong API group or skipping spec.plugins.   Watch. Hard-coding the Loki URL in fetch().

            Guide topic. Design

            Language

            Glossary

            ACM

            Advanced Cluster Management. Multi-cluster; often Thanos for metrics and a different alerting path.

            Alertmanager

            Routes and groups Prometheus alerts. Incidents sit above raw alert floods.

            CMO

            Cluster Monitoring Operator — default in-cluster Prometheus stack on OpenShift.

            ConsolePlugin

            CR that registers a dynamic plugin: assets service, optional proxy, display name.

            COO

            Cluster Observability Operator — installs optional Observe UIs, Perses, incidents, related backends.

            CRC / OpenShift Local

            A laptop-sized OpenShift cluster for plugin loops.

            DCO

            Developer Certificate of Origin. Commits need Signed-off-by for many OpenShift repos.

            Dynamic plugin

            Webpack 5 module federation: the console loads your JS at runtime.

            Exemplar

            A trace id attached to a metric sample so the UI can jump metric → trace.

            GitOps Console spec

            If git owns the Console CR, plugin names must live there or a sync disables them.

            Korrel8r

            Correlation engine: rules that link alerts, metrics, logs, pods, netflows.

            LogQL

            Loki query language. Stream selector, then line filters, then unpack.

            Loki / LokiStack

            Log store. Observe → Logs talks to it through a plugin proxy.

            OTel

            OpenTelemetry: collector pipeline + semantic conventions. Not a React library.

            OWNERS

            File that lists who can approve a repo area. Read it before you ping randomly.

            PatternFly 6

            OpenShift console design system from 4.19+. Do not import its CSS in a plugin.

            Perses

            Cloud-native dashboards as Kubernetes CRs. Observe → Dashboards (Perses).

            PromQL

            Prometheus query language. Instant vs range; rate on counters.

            spec.plugins

            Console Operator list of enabled dynamic plugins.

            spec.proxy

            ConsolePlugin field: console backend proxies to an in-cluster Service.

            Tempo

            Trace store used with the current tracing UI. Jaeger is legacy conversation.

            Thanos

            Long-term / multi-cluster metrics path (often with ACM).

            TraceQL

            Tempo’s language to find traces by service, duration, attributes.

            Troubleshooting panel

            Console graph UI over Korrel8r results; clicks must map to real routes.

            UIPlugin

            COO CR that selects which Observe UI extras to install.

            viaq

            Legacy OpenShift logging schema. OTel schema is the other switch in the logs UI.

            WCAG

            Accessibility standard. Keyboard, contrast, name/role/value — in the job, not polish.
